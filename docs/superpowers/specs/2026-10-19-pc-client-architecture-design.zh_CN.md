# 电脑客户端、手机遥控和云端遥控通道 —— 架构设计

状态：2026-10-19 已决定（见「决定」）。P1（核心）和 P3a（带镜像的 ffmpeg 下载）已在分支 `desktop-core` 上实现，P2 在 `desktop-tray` 上，`v0.2.0-beta` 剩下的（受信任的网络、`listening`、打标签发布、中文安装向导）在 `desktop-finish` 上；各阶段的状态见第 13 节。本文**取代**
[`2026-10-15-self-hosting-design.zh_CN.md`](2026-10-15-self-hosting-design.zh_CN.md) 的方向：家庭服务器不再
「Docker 优先」，而是变成 Windows 和 macOS（Linux 算附带）上的一个桌面程序，用的还是同一套核心。那份文档的
S1 和 S3 已实现，原样沿用；它的结论（局域网明文 HTTP 下的 cookie、前端的两个端口、不带内容的规则、安全上下文
那张表、gate-lite）仍然成立，这里只引用、不重复。同时承接
[`2026-10-12-multi-tenant-design.zh_CN.md`](2026-10-12-multi-tenant-design.zh_CN.md)
（账号、绑定、会话、总后台；阶段 4 媒体网关没做）、
[`2026-10-12-phone-audio-design.zh_CN.md`](2026-10-12-phone-audio-design.zh_CN.md)、
[`2026-10-12-voice-control-design.zh_CN.md`](2026-10-12-voice-control-design.zh_CN.md)、
[`2026-10-13-wifi-setup-design.zh_CN.md`](2026-10-13-wifi-setup-design.zh_CN.md) 和
[`2026-10-13-sound-provisioning-design.zh_CN.md`](2026-10-13-sound-provisioning-design.zh_CN.md)。

需求：你不想在自己的服务器上替所有人扛视频，一是成本，二是风险。产品变成在用户家里跑的三部分，外加一台由你
掌控的可选服务器：

1. 设备上的**固件**（星智 Cube 1.54，ESP32-S3；AI Passport，ESP32-C3）。已完成：公开构建、发布流程、网页刷机。
2. **电脑客户端**：家里一台 Windows 或 Mac 电脑上的程序，拉取内容、转码，在家里局域网上推给设备。
3. **手机遥控**：现有的网页遥控，局域网里由电脑客户端提供；出门在外时经你服务器上一个很小的**云端遥控通道**
   使用，这个通道只走遥控消息。
4. **可选服务器**：你现有的云主机和它的账号体系，只给你挑中的、家里没有电脑的少数人用，带有效期和限额。

下文用语：**电脑客户端**（或「客户端」）是这个桌面程序；**核心**是它运行的 Python 程序（就是现在
`server/selfhost` 的监督进程和它的子进程）；**中继**（hub）是你主机上的云端遥控通道服务；`<public-domain>` 是你
的公开 HTTPS 域名；`<owner-server>` 是你的云主机；`<static-site>` 是项目的静态网站。标了**推算**的数字都还没实测。

## 已经和你定下、这里不再讨论的

- 电脑客户端**先做方案 A**：现有的 Python 核心用 PyInstaller 打包，加一个系统托盘图标，界面就是现有的网页，用默认
  浏览器在 `localhost` 打开。**方案 B**（Tauri 外壳包住同一套网页、核心作为 sidecar）是以后的升级路线；A 要设计成
  B 不需要改核心（第 5.13 节）。
- Windows 和 macOS 都重要；Linux 算附带。
- 家里有电脑的家庭，视频永远不经过你的服务器。设备带出门时改用可选服务器的账号。
- 家里没有公网 IP 时，手机在外面也要能遥控，而且不用端口转发，走**我们自己的云端遥控通道**：电脑保持一条到你
  服务器的出站连接；手机打开公开网站；服务器把命令转给那一家的电脑。
- 语音识别（SenseVoice，约 550 MB 内存）在电脑本机跑，作为可选下载。
- 客户端自己能刷固件（自带 esptool），不受浏览器网页串口的限制。
- 有设备在看时不让电脑睡眠。
- ffmpeg 随包带或首次运行时下载，注意 LGPL 和 GPL 构建的区别。
- 测试版不签名，配一篇教程讲怎么放行（macOS Gatekeeper、Windows SmartScreen）；正式发布前买 Apple Developer ID
  和 Windows 代码签名证书。
- YouTube 要用户自己的代理或节点；不提供获取方法。

## 1. 什么东西挪到哪里

### 1.1 现在

你的云主机替它服务的所有人扛下一切：带账号的中转、媒体服务（每个型号一个）、所有视频（每台星智约 1.7 Mbit/s，
总共 3 Mbit/s）、手机遥控、总后台、语音识别、YouTube 节点的连接。自建的家庭（v0.1.0-beta）用 Docker 或
`./run.sh --selfhost` 在家里跑同一套核心，需要一个懂技术的人。

### 1.2 这份设计之后

| 部分 | 现在 | 之后 |
| --- | --- | --- |
| 转码、推流给设备 | 你的主机（或某家的 Docker） | **家里的电脑客户端**；你的主机只给可选账号用 |
| 拉取片源（B 站、直播、经用户自己节点的 YouTube） | 你的主机 | 电脑客户端，用家里的地址（B 站不会对它回 412） |
| 局域网里的手机遥控 | 你的主机或家庭服务器 | 电脑客户端（`http://<电脑>:8080/tv/`） |
| 在外面的手机遥控 | 你的主机，或家里自己搭的隧道 | 你主机上的**中继**：把加密的小 API 调用转给电脑；网页是静态文件 |
| 用手机听（HLS 音频） | 你的主机 | 电脑客户端，**只在局域网**（Q3） |
| 账号、设备、进度、订阅 | 你主机的数据库 | 电脑客户端自己的数据库（一家）；你的主机只管可选账号 |
| 语音识别 | 你的主机（`muse-asr`） | 电脑客户端，可选本机下载 |
| 刷固件 | `<static-site>` 上的网页刷机，或家庭服务器的 `localhost` 版 | 一样，另加客户端内置刷机 |
| 总后台 | 你的主机（所有用户） | 每个电脑客户端各有一个（一家）；你的 `/tv/admin` 管可选账号和中继上的家庭 |
| 静态网站、教程、下载、`latest.json` | `<static-site>` | 一样；安装包另放一份国内镜像 |

之后你的主机只扛：中继（空闲连接，加上每条命令几 KB）、静态遥控页面，以及可选账号的视频流（受 3 Mbit/s 限制）。

## 2. 目标和非目标

用户是不懂技术的家庭，家里有一个人负责一次性安装程序（下载、双击、在系统警告里放行）并给设备刷机。不用终端，
不用 Docker，不用改路由器。

目标：

1. **像普通软件一样安装**，支持 Windows 10/11 和 macOS 12 及以上（Apple 芯片和 Intel）：一个安装包或 `.dmg`，
   托盘或菜单栏里一个图标，登录后自动启动。
2. **第一次运行在浏览器里完成**：客户端打开 `http://localhost:<端口>/tv/setup`，设置码已经填好；建管理员不需要看日志。
3. **和 Docker 镜像、云主机同一套核心**：客户端是运行 `server/` 的一种方式，不是分叉。Docker 和直接用 Python
   跑的方式留给 NAS 和无界面的机器。
4. **在哪都能用手机遥控**，不用端口转发，你的服务器也看不到在看什么（端到端加密，第 7.6 节）。
5. 一台电脑**同时服务多台设备**（gate-lite，自建设计的 S2），跨平台。
6. **自带所需**：ffmpeg、刷机、（可选）语音随客户端带，或由它按固定的哈希下载。
7. **不带内容**，不收集遥测，没有共享密钥。
8. **为方案 B 做好准备**：托盘做的所有事都经过一个本机控制接口，Tauri 外壳可以直接替换托盘，不改核心。

非目标：

- 有电脑的家庭的视频或「用手机听」的音频经过你的服务器。
- 应用商店版本（Mac App Store、Microsoft Store）或手机 App。
- 作为 Windows 服务或 macOS 启动守护进程在登录前运行（客户端在用户会话里跑；NAS 和无界面用户继续用 Docker）。
- 32 位 Windows；Windows on ARM 不作为支持目标（x64 版靠模拟能跑，未测）；比 macOS 12 更老的系统。
- 改设备的通信协议、码率控制器或计时代码。
- 第一版就做手机和电脑之间的点对点（WebRTC）（第 7.11 节）。

## 决定（2026-10-19）

你接受了全部建议（Q1–Q15 都按每题的建议）。先做 `v0.2.0-beta`：P0 的小试验、P1、P2、P3a 和部分 P10（电脑客户端，每个型号一台，局域网遥控）。

## 3. 需要你决定的问题

每个都有选项和推荐；文档其余部分按推荐写。

### Q1. 第一个远程版本就做手机和电脑之间的端到端加密吗？

| 选项 | 后果 |
| --- | --- |
| **A. 一开始就做** | 多 2.5–3.5 个 agent-day（第 7.6 节）。中继只看得到路由 id、大小和时间；永远看不到会话令牌、片名、订阅，以及遥控可以发给设备的 Wi-Fi 密码。你可以如实说自己只转发密文。局限：网页的 JavaScript 来自你的服务器，被攻破的服务器可以下发一个泄露密钥的页面；端到端加密防的是日志、数据库泄露和随手查看，防不了存心作恶的运营者。 |
| B. 只到中继的 TLS | 做得快。中继能解开一切：每家的会话令牌和 Wi-Fi 密码都以明文经过你的服务器，任何日志或漏洞都会泄露它们。以后再开端到端加密要所有手机重新配对。 |

**推荐：A。** 不做的话，远程时 Wi-Fi 管理功能只能关掉，而你的服务器会握着每一家的凭据。

### Q2. 谁能把电脑接到中继上？

| 选项 | 后果 |
| --- | --- |
| **A. 测试版：凭 `/tv/admin` 发的邀请码；正式版：开放，带配额** | 规模小的时候你知道谁在用；陌生人占不满它。正式发布时开放注册，配每家的配额和按网段的注册限制（第 7.9 节）。 |
| B. 一开始就开放 | 装了客户端的人都能注册。中继不走内容、不转发各家的 HTML，被滥用最多是耗配额，但你不知道上面都是谁。 |
| C. 永远只凭邀请 | 每家都得来找你；超出朋友圈就做不下去。 |

**推荐：A。**

### Q3. 出门在外能用手机听吗？

| 选项 | 后果 |
| --- | --- |
| **A. 只在局域网** | 中继什么都不用改。在外面遥控照常可用，「用手机听」按钮说明「只能在家用」。 |
| B. 经中继、带限制 | 每部在听的手机约 4–5 kB/s（32 kbit/s AAC）走你的 3 Mbit/s，约 60 部就满了；而且是内容（音频）经过你的服务器，破坏了「服务器不走内容」；HLS 也没法让 `<audio>` 元素解密，所以不在端到端加密之内。 |

**推荐：A。**

### Q4. 主屏幕上放一个图标还是两个？

公开的遥控页（`https://<public-domain>/r/`）调不了电脑在局域网里的明文 HTTP 地址（混合内容，以及浏览器对私有网络
的限制），所以用它的手机即使在家也走中继。

| 选项 | 后果 |
| --- | --- |
| **A. 一个图标，公开页面，总是经中继** | 对家庭最简单。每个在前台的遥控页给你的主机带来约 0.1–0.8 kB/s（第 7.10 节）。局域网页面仍然可用（设备上的二维码、电脑版）。 |
| B. 两个图标，「在家」（局域网）和「外出」（中继） | 中继流量更少；家里人得选对图标。 |

**推荐：A**，配中继的带宽保护（第 7.9 节）。实测中继流量超出预算时再议。

### Q5. ffmpeg：首次运行下载，还是随包带我们自己的 LGPL 构建？

| 选项 | 后果 |
| --- | --- |
| A. 保持现在的首次运行下载（`tools/ffmpeg_fetch.py`：从 PyPI 取 `imageio-ffmpeg` 的 wheel，版本和 SHA-256 写死） | 现在在 Windows 和 macOS 上能用。这些是 GPL 构建，所以才「下载」而不是「分发」。首次运行要能访问 PyPI（国内能访问，部分地区慢；哈希写死，所以任何镜像都安全）。Linux 版是全静态的，在云主机上解析不了主机名。 |
| **B. 我们自己的最小 LGPL 构建，随包带** | 核心只需要解码器、解复用器、`scale`/`pad`/`fps`/`aresample`、自带的 AAC 编码器、`rawvideo`/`s16le` 输出和 HTTP(S)（第 5.7 节）。每个平台在 CI 里编一份（每份约 5–10 MB），连同源码和配置参数一起发布。第一次运行不用联网。1–2 个 agent-day。 |

**推荐：测试版用 A，1.0 用 B**，A 的下载保留作后备，并加上国内镜像。

### Q6. macOS 版：两个 DMG 还是一个通用版？

**推荐：** 测试版先在两台构建机上出两个 DMG（Apple 芯片、Intel）；等客户端去掉 numpy（第 5.8 节）后再试 `universal2`，
因为卡住通用版的通常就是不同架构的 wheel。

### Q7. Windows 安装包

| 选项 | 后果 |
| --- | --- |
| **A. Inno Setup，按机器安装（弹一次 UAC）** | 装到 Program Files，给核心加一条只在**专用**网络生效的防火墙规则，加开始菜单和开机自启。不签名也能用（SmartScreen 会警告）。 |
| B. Inno Setup，按用户安装，不要管理员 | 没有 UAC 弹窗，但第一次监听端口时会弹防火墙询问，标准账户要管理员密码才能放行；很多家庭会点掉，设备就连不上。 |
| C. MSIX | 不签名的话，开发者模式以外装不上。签名之后需要再说。 |

**推荐：A。**

### Q8. 自启动和睡眠

**推荐：** 默认登录后自动启动（托盘里有开关）。有设备连着或有手机在听时，阻止系统闲置睡眠；从不让屏幕常亮；托盘
里加一个「小智电视运行时不让电脑睡眠」的开关，给希望随时能看的家庭（睡着的电脑接不了刚开机的设备）。

### Q9. 内置刷机

| 选项 | 后果 |
| --- | --- |
| A. 只用网页刷机，在 `http://localhost:<端口>/flash/` 打开（现在就能用：`localhost` 算安全上下文） | 不用写新代码；要用 Chrome 或 Edge（Safari 和 Firefox 没有网页串口）。 |
| **B. 内置刷机，用乐鑫官方的 esptool 可执行文件，作为单独的进程运行** | 任何浏览器都行，还能把电脑的地址直接写进刚擦除的星智（第 6.1 节）。esptool 是 GPLv2：作为随包带的独立程序运行（不导入到我们的进程里），附许可证和源码链接。2–3 个 agent-day。 |

**推荐：测试版 A，1.0 用 B。**

### Q10. 可选服务器账号：到期那天怎么办？

**推荐：** 到 `valid_until` 就停（没有宽限期）：会话结束，这个用户的设备收到一张静止画面「使用权已于某日结束，请联系
某某（管理员名字）」，不再转码；到期前 7 天在遥控页上提醒；新开通的默认值：1 台设备、同时 1 路、3 个月；用户页上
一键延期。

### Q11. 中继放在哪？

**推荐：** 测试版以及大约 1,000 个已连接家庭以内，放在现在的主机上、它的 nginx 后面（第 7.10 节）。中继实测的流量或
连接数接近预算时，把它单独搬到一台按流量计费的小实例上（中继的总流量不大，紧的是 3 Mbit/s 的峰值），域名不变。

### Q12. 更新

**推荐：** 客户端每天查一次 `<static-site>` 上签过名的 `latest.json`（不带任何标识；设置里可以关），提示「有新版本」；
用户点了才从 GitHub Releases 或国内镜像（对象存储）下载安装包，核对 SHA-256 和清单的 Ed25519 签名，然后替用户打开
安装包。测试版不做静默更新。签名私钥离线放在你手里。

### Q13. 代码签名的时间和预算

**推荐：** 测试版不签名，配教程（第 5.12 节）。正式发布前：Apple Developer Program（每年 99 美元，含公证），以及
一张 Windows OV 代码签名证书（每年约 1,500–3,000 元起；2024 年起 EV 证书不再直接带 SmartScreen 信誉，所以 OV 就够；
Azure Trusted Signing 更便宜，但据目前所知不对中国大陆的个人开放，待核实）。

### Q14. 版本号

仓库里同时有上游的 `v1.0.0`–`v1.3.0`（单用户服务器）和本分支的 `v0.1.0-beta`。**推荐：** 电脑客户端继续用 `v0.x`
测试版（`v0.2.0-beta`：客户端；`v0.3.0-beta`：中继），第一个正式版定为 `v2.0.0`，这样在任何版本比较里（更新检查、
发布列表）都排在上游的标签之上。

### Q15. 你自己的设备

**推荐：** 你家里的设备改用你自己的电脑客户端（把云主机的 3 Mbit/s 腾给你开通的人），云主机上留一台测试设备，你的
管理员账号留在那里管可选用户。

## 4. 总览

```
                              家里的局域网
   ┌───────────────────────────────────────────────────────────────┐
   │  电脑客户端（Windows / macOS / Linux）                          │
   │   托盘 ─ 本机控制接口 ─ 核心监督进程                             │
   │            中转 · 前端 :8080 · 媒体 :8097/:8098（网关）          │
   │            ffmpeg · 可选语音识别 · 中继代理                      │
   │      ▲ 原始 TCP（画面、声音）       ▲ HTTP（局域网遥控）          │
   │   设备（星智、Passport）          在家的手机                     │
   └──────────────────────────────────────┬────────────────────────┘
                                          │ 一条出站 WSS，只有密文
                                          ▼
   ┌───────────────────────────────────────────────────────────────┐
   │ <owner-server>（2 vCPU，可用约 1.8 GB，出网 3 Mbit/s）            │
   │  nginx ── /r/ 静态遥控页面（按版本）                              │
   │       ── /hub/ 中继：把手机的调用转给那一家的电脑                   │
   │       ── /tv/ 可选账号的中转和总后台（和现在一样）                  │
   │  媒体服务 :8097/:8098，只给可选账号                               │

## 5. 电脑客户端（方案 A）

### 5.1 进程结构

```
XiaozhiTV（托盘进程，图形界面主线程）
 │  读 <数据目录>/run/control.json（端口 + 令牌），只和控制接口说话
 └─ 启动并看着 ──► xiaozhi-tv-core selfhost --data <数据目录> --desktop
                    监督进程（server/selfhost），提供控制接口 127.0.0.1:<随机端口>
                    ├── 中转   127.0.0.1:8099 / :8100
                    ├── 前端   0.0.0.0:8080（局域网），127.0.0.1:<隧道端口>（只给中继代理）
                    ├── 媒体   :8098 星智，:8097 Passport（S1）→ 网关 + 每台设备一个工作进程（S2）
                    ├── 中继代理  出站 WSS 到 <public-domain>/hub/（开启时）
                    ├── 语音识别  127.0.0.1:<端口>（可选）
                    └── 电源    阻止睡眠（在监督进程里）
```

- **顶上是两个进程，不是一个。** 托盘工具包要占主线程（macOS 的 AppKit 必须如此）；监督进程要装信号处理，Python
  只允许在主线程装。一个崩了不会拖垮另一个，方案 B 也只替换上面那个。
- **核心就是现在的监督进程**（`server/selfhost/__main__.py`、`supervisor.py`），加一个 `--desktop` 开关处理下面这些
  不同。Docker 和 `./run.sh --selfhost` 不带这个开关，照旧。
- **打包后的子进程。** 监督进程用 `sys.executable -u -m server.relay …` 启动子进程（`server/selfhost/supervisor.py`
  的 `python_command()`）。PyInstaller 构建里 `sys.executable` 是程序本身，`-m` 没有意义，这正是现在
  `tools/launch.py` 在打包版里拒绝 `--selfhost` 的原因。客户端需要 `tools/packaged_entry.py` 已经给单用户服务器做过
  的那种分派（`__media`、`__config`），扩展到 `__selfhost`、`__relay`、`__front`、`__gate`、`__worker`、
  `__hub-agent`、`__asr`；打包时 `python_command()` 返回 `[sys.executable, "<子命令>"]`。
- **父进程没了，子进程跟着走。** POSIX 上监督进程的子进程在它的进程组里，停的时候一起结束。Windows 上
  `terminate()` 就是 `TerminateProcess`，媒体服务的 ffmpeg 孙进程会留下来继续占着端口。`tools/parentwatch.py`
  已经给单用户启动器解决了这个问题（Windows 上用带 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` 的作业对象，POSIX 上用一条
  从不写的管道）；监督进程和托盘都用它。托盘把核心放进自己的作业里，所以退出或强杀托盘都会停掉一切。
- **只开一个。** 托盘在 `<数据目录>/run/` 里拿一个锁；锁被别的实例拿着时，就（经控制接口）让那个实例打开电脑版，
  自己退出。

### 5.2 各系统的打包

所有平台都用 PyInstaller **onedir**，不用 onefile：onefile 程序每次启动都要把自己解压到临时文件夹，而核心要从同一个
程序启动五个以上的进程（有了网关以后，每台在播的设备还要一个，而且要在 2 秒内起来，第 6.3 节）。onedir 被杀毒软件
误报也少，LGPL 组件也能被替换。

| 系统 | 产物 | 内容 | 在哪构建 |
| --- | --- | --- | --- |
| macOS，Apple 芯片 | `XiaozhiTV-<版本>-macos-arm64.dmg` | `Xiaozhi TV.app`（`LSUIElement`：只在菜单栏，不进程序坞），onedir 核心在 `Contents/MacOS/` 里，带 ffmpeg、esptool；一个指向「应用程序」的链接 | `macos-14`/`macos-15` 构建机 |
| macOS，Intel | `XiaozhiTV-<版本>-macos-x86_64.dmg` | 同上，x86_64 | 一台 Intel 构建机（`macos-15-intel` 或到时 GitHub 提供的；构建前确认） |

  局域网里的片源，以后还会为了发现设备去连设备）；`NSAppSleepDisabled`（不进 App Nap：核心的节奏不能被节流；要在
  macOS 14/15 上验证）。
- **发布流程** 从 `.github/workflows/build-server.yml`（现在：每个平台一个 onefile 的单用户 `tv-server`，macOS 只有
  arm64）扩展成新的 `build-desktop.yml`，矩阵如上表；冒烟测试用临时数据目录以 `--desktop` 模式启动打包后的核心，查
  `/healthz`，用模拟设备（`tools/device_sim.py`）拿到「未绑定」画面，并检查每个子进程的打包分派。单用户构建保留到
  发布说明里由客户端取代为止（第 10 节）。
- **发布说明。** `build-server.yml` 里的发布正文是上游的单用户说明（8096 端口、`FoloToy-XXXX` 热点、上游的链接）；

  然后是固件和网页刷机，家用服务器算进阶，不签名测试版的步骤；先中文后英文），固件、服务器、电脑客户端三个发布任务都发它。
  推标签时 `build-desktop.yml` 把两个 DMG、Windows 安装包和免安装 zip、Linux 压缩包连同 `SHA256SUMS-desktop`（不叫
  `SHA256SUMS`：那是固件的）发到同一个发布；别的运行是试运行，做到检查过的文件集为止。

### 5.4 第一次运行

```
安装、启动 ─► 托盘出现 ─► 核心第一次启动（和现在的引导一样）：
   数据目录、config.toml、密钥、tv.db（meta.selfhost=1）、设置码
 ─► 有 ffmpeg 吗？（随包带的；或者下载，托盘里显示进度，Q5）
 ─► 托盘打开 http://localhost:8080/tv/setup#<设置码>   （设置码不出这台电脑）
 ─► 页面：家庭名称、管理员名字 ─► 建好管理员，浏览器已登录
 ─► 「连接你的手机」：二维码 = http://<局域网 IP>:8080/TV/P/<手机链接>（现有的手机登录方式）

- S1 的设置码机制保留（证明管理员就在这台电脑前）；客户端把它放在网址的片段里交给本机浏览器，不用任何人看日志。
  局域网里没有设置码的访客仍然拿不走服务器。
- **本机管理员登录。** 「打开电脑版」向控制接口要一个一次性登录链接（和应急用的
  `python3 -m server.tenancy.admin login-link` 同一个机制），60 秒有效，只认本机。能用控制接口的人本来就能读用户的
  文件，所以这不多给任何权限。
- **端口被占。** 8080 被占时（开发者的电脑上很常见），核心依次试 8090、18080、28080，记下拿到的那个；反正手机用的
  是二维码。8097 和 8098 不能换（固件默认的端口）；被占时托盘说明是哪个程序占着。

### 5.5 各系统的数据、设置和日志

每个用户一个文件夹，布局和 S1 一样（`config.toml`、`secrets/`、`tv.db`、`devices/`、`channels.txt`、`backups/`、
`run/`、`firmware/`、`models/`），另加 `logs/` 和 `bin/`（下载的 ffmpeg、esptool、语音运行库）。

| 系统 | 数据 | 日志 | 程序 |
| --- | --- | --- | --- |
| Windows | `%LOCALAPPDATA%\XiaozhiTV\` | `…\XiaozhiTV\logs\` | `C:\Program Files\Xiaozhi TV\` |
| macOS | `~/Library/Application Support/XiaozhiTV/` | `~/Library/Logs/XiaozhiTV/` | `/Applications/Xiaozhi TV.app` |
| Linux | `$XDG_DATA_HOME/xiaozhi-tv/`（`~/.local/share/…`） | `$XDG_STATE_HOME/xiaozhi-tv/logs/` | 解压到哪就在哪 |

- **Windows 上用本地的，不用漫游的。** `tools/datadir.py` 现在用 `%APPDATA%`（漫游）；放在漫游配置里的 SQLite 数据库
  在域环境里可能被同步到一半。客户端用 `%LOCALAPPDATA%`。
- **从测试版迁移。** 如果 `<用户数据目录>/selfhost`（直接用 Python 跑的测试版的文件夹）存在而客户端的文件夹不存在，
  第一次运行时提议沿用它；布局是一样的。
- **非 ASCII 路径。** Windows 上中文用户名很常见；冒烟测试用一个路径里带中文的数据目录跑（ffmpeg 参数、SQLite 路径、
  日志）。
- **密钥。** `os.chmod(0o600)` 在 Windows 上起不了作用；保护靠的是每个用户 `%LOCALAPPDATA%` 的权限，备份时的提醒照旧。

### 5.7 ffmpeg

核心要 ffmpeg 做的事（来自 `server/live.py`、`server/media.py`、`server/frames.py`、`server/listen.py`）：读 HTTP(S)/HLS/
FLV/MP4 片源，解码常见视频（H.264、HEVC、MPEG-2、VP9，AV1 可选）和音频（AAC、MP3、AC-3、Opus），滤镜 `scale`、
`pad`、`setsar`、`fps`、`format`、`showinfo`、`setpts`、`aresample`、`aformat`、`asetnsamples`、`ashowinfo`、
`anullsrc`，自带的 `aac` 编码器（用手机听），以及经 TCP 输出 `rawvideo`/`s16le`。**没有只在 GPL 里才有的东西**（没有
libx264，没有 GPL 滤镜），所以 LGPL 构建就够。

| 阶段 | 怎么做 | 许可证 |
| --- | --- | --- |
| 测试版（Q5 A） | 和现在一样用 `tools/ffmpeg_fetch.py`：写死的 `imageio-ffmpeg` 0.6.0 wheel，核对 SHA-256，缓存在 `<数据目录>/bin/`；加镜像地址（哈希写死，任何镜像都安全），托盘里显示进度 | GPL 构建，由用户自己的电脑下载，不是我们分发（这个模块存在的原因） |
| 1.0（Q5 B） | CI 给每个平台编一个最小 LGPL ffmpeg（`--disable-gpl --disable-nonfree --disable-everything` 再加上面列的那些；TLS 在 macOS 上用 SecureTransport，Windows 上用 Schannel，Linux 上用 OpenSSL 3 或 GnuTLS），随应用带 | LGPL 2.1+：把完全对应的源码包和构建脚本作为发布附件，许可证写进应用的 `NOTICE`，ffmpeg 保持为可替换的独立程序 |

Linux 上原来的说明仍然成立：下载的静态版在云主机上解析不了主机名；Linux 客户端优先用系统里的 ffmpeg，再用随包带的
LGPL 版。

### 5.8 numpy 和画面降级

默认的降级方式 `steady` 不需要 numpy（`server/degrade.py`）；要 numpy 的那些方式（`perceptual`、`mosaic`）是实验用的。
客户端**不带 numpy**：小 20–30 MB，工作进程启动更快，macOS 也有可能出通用版。客户端里 `TV_DEGRADE` 除了
`steady`/`ladder` 一律拒绝并给出清楚的提示，`server/live.py` 在没有 numpy 时已经这么做。

### 5.9 可选的语音

- **默认关**；电脑版的设置里提供「语音（下载约 300 MB，开着时占约 550 MB 内存）」。下载：对应平台的 sherpa-onnx
  运行库和 SenseVoice-Small 模型，从镜像下，哈希写死，下载前展示模型的许可证（和自建设计一样，许可证还要核实）。
- 作为监督进程的子进程（`__asr`）运行，不是容器。**套接字要换：** `server/voice/asr.py` 走 Unix 套接字上的 HTTP，
  CPython 在 Windows 上没有 Unix 套接字；客户端改用回环 TCP，请求头里带中转密钥。云主机继续用 Unix 套接字。
- 内存小于 8 GB 时，开启前先警告。

### 5.10 阻止睡眠

| 系统 | 机制 | 范围 |
| --- | --- | --- |
| Windows | 经 ctypes 调 `SetThreadExecutionState(ES_CONTINUOUS \| ES_SYSTEM_REQUIRED)`，在监督进程里一个一直活着的线程上调 | 只管闲置睡眠；从不加 `ES_DISPLAY_REQUIRED`。用户自己点睡眠、合上笔记本盖子照样会睡 |
| macOS | 经 ctypes（IOKit）建一个 `PreventUserIdleSystemSleep` 类型的 `IOPMAssertion`；最简单的后备是起一个 `caffeinate -i -w <核心 pid>` 子进程 | 只管闲置睡眠。合上 MacBook 盖子会睡，除非插着电源并接了外接显示器 |
| Linux | 有的话起一个 `systemd-inhibit --what=idle:sleep` 子进程 | 同上 |

第一台设备连上或第一部手机开始听时拿住，最后一个离开 2 分钟后放开（监督进程读媒体服务的 `now-playing` 文件，它为
`/healthz` 本来就在看）；`keep_awake = "always"` 时核心运行期间一直拿着。系统电源计划仍会让电脑睡时（笔记本用电池、
合盖），托盘会说明。以后的想法：服务器不应答时，设备向电脑的 MAC（经 CONFIG 告诉它）发一个网络唤醒包；只对开了 WoL
的有线台式机有用。

### 5.11 防火墙和网络暴露

- **Windows：** 安装包给核心程序加只在**专用**网络生效的入站规则。最常见的故障是家里的 Wi-Fi 被标成**公用**：核心
  启动时查一次（`netsh`/WMI，相当于 `Get-NetConnectionProfile`），托盘告诉用户怎么改成专用。
- **macOS：** 应用防火墙默认是关的；开着时会为核心弹询问。临时签名（未签名）的应用每次更新后都会再问一次；签名
  后就好了（Q13）。
- **受信任的网络：** 带着笔记本去咖啡馆，8080/8097/8098 就会暴露在那里的网络上。用户第一次确认「这是我家的网络」时，
  客户端按路由器的身份（默认网关的 MAC 地址）记住家里的网络；在别的网络上核心把局域网端口只绑在 `127.0.0.1`（中继
  代理照常工作）。约 1 个 agent-day；值得做，因为测试版用户大多会在笔记本上跑。
- **实际实现（`desktop-finish`）：** `server/selfhost/network.py`，路由器身份和判断用 `tools/netcheck.py`（和托盘共用）。
  每 15 秒读一次网关，新的读数连续两次一样才算数（ARP 表一时没有条目、Wi-Fi 重连），开/关的判断变了就按新的地址重启
  子进程（`Supervisor.rebuild_requested`）。还没记下任何网络（「询问」）时照常开放，因为第一次运行几乎总在家里；记下家里
  以后，认不出的路由器（没联网、有的 VPN）算不在家；「这不是我家的网络」也会记下。列表存在 `desktop.json`；`config.toml`
  里 `bind = "127.0.0.1"` 时什么都不开放。Windows 网络类型也由核心查（一分钟一次），变成问题 `network_public`，只在端口
  开着时报。
- **局域网地址（`desktop-addr`）：** `server/netident.py` 用系统自带的命令列出 IPv4 地址和默认路由（macOS `ifconfig`、
  `netstat -rn -f inet`；Linux `ip -4 -o addr` / `ip -4 route show default`，没有就读 `/proc/net/route` 和 `hostname -I`；
  Windows 一次 PowerShell（`Get-NetAdapter -Physical`、`Get-NetIPAddress`、`Get-NetRoute`，输出 UTF-8），不行就按结构读
  `ipconfig`，不认字），选带着家里路由器（某条默认路由的下一跳在它的网段里）的那张网卡上的地址，私有地址和物理网卡优先。
  从不选：198.18.0.0/15（代理的 TUN 模式）、100.64.0.0/10（Tailscale）、链路本地、回环、隧道（`utun`、`tun`、`wg`、点对点、
  wintun 的名字）；虚拟网卡和网桥（Docker、libvirt、VMware、VirtualBox、Hyper-V、网络共享）只在带着路由器时选。原来的 UDP
  探测留作最后的办法，结果落在这些网段里时不用。第一次设置时记进数据库的 `device_address`、`public_url` 落在这些网段里、
  或者已经不是这台电脑的地址时不用（`.local` 名字照用）；`config.toml` 写的总是优先，设置页也不再记下这种地址。运行中，
  看受信任网络的线程也看地址：每 15 秒一次便宜的检查（UDP 探测和路由器身份，不起进程），变了、以及每 5 分钟完整列一次，
  新地址连续两次一样才算数；设备地址或网站地址变了就重建子进程。`POST /local/v1/restart` 先重读 `config.toml`（端口和
  `bind` 除外）和地址，再重建子进程。

### 5.12 不签名的测试版：用户会看到什么、教程怎么写

- **macOS 15 及以上：** 右键「打开」已经绕不过 Gatekeeper。教程这样写：打开应用，点「完成」（不要点「移到废纸篓」），
  系统设置 > 隐私与安全性 >「仍要打开」，再确认。还有：先把应用拖进「应用程序」（直接从挂载的 DMG 里运行会被
  「转移」，数据路径就不对了）。构建是临时签名的，这是 Apple 芯片的要求。
- **Windows：** SmartScreen「Windows 已保护你的电脑」> 更多信息 > 仍要运行。Windows Defender 有时会误报 PyInstaller
  的引导程序：用 onedir、在 CI 里从源码编引导程序、向微软提交误报，都能减少；教程说明怎么核对发布的 SHA-256。
- 每次发布都附 `SHA256SUMS` 和它的 Ed25519 签名（Q12），细心的用户可以自己核对下载。

### 5.13 本机控制接口和方案 B

托盘做的每件事都经过同一个 HTTP 接口，由监督进程在 `127.0.0.1:<随机端口>` 提供，端口和一个随机令牌写在
`<数据目录>/run/control.json`（权限 0600，在每个用户自己的文件夹里）。请求头里带令牌，没有的一律拒绝。

| 接口 | 用途 |
| --- | --- |
| `GET /local/v1/status` | 版本、端口、局域网网址、设备和它们在放什么、ffmpeg、语音、中继状态、有没有更新 |
| `POST /local/v1/console-link` | 给浏览器（或网页视图）的一次性管理员登录网址 |
| `POST /local/v1/phone-qr` | 局域网的手机登录网址；开了中继时加上配对网址（第 7.4 节） |
| `POST /local/v1/remote/enable`、`/disable`、`/forget-phones` | 中继注册和配对 |
| `POST /local/v1/power`、`/autostart` | 托盘上的开关 |
| `POST /local/v1/flash/*` | 内置刷机（第 6.1 节） |
| `POST /local/v1/update/check`、`/update/download` | 更新（5.14） |
| `POST /local/v1/diagnostics` | 生成诊断信息压缩包（5.15） |
| `POST /local/v1/restart`、`/stop` | 启停 |

**方案 B（Tauri）** 只替换托盘进程：Tauri v2 外壳启动同一份 onedir 核心（作为资源打包，经 shell 插件启动，因为 Tauri
的 `externalBin` sidecar 要求是单个文件），读 `control.json`，经 `console-link` 在网页视图里显示电脑版，托盘内容来自
`/local/v1/status`。核心不改。B 带来的：真正的窗口而不是浏览器标签页、系统通知、更像原生应用；代价：4–6 个
agent-day、CI 里多一套 Rust 工具链、Windows 上要 WebView2（当前的 Windows 10/11 都有），签名照样要做。

#### 实际实现的约定（P1c）

这是核心（P1，分支 `desktop-core`）和托盘（P2）或以后的 Tauri 外壳之间的接口。这里没写的都不算约定。

**启动核心。** onedir 构建是一个文件夹 `xiaozhi-tv-core/`，里面的可执行文件叫 `xiaozhi-tv-core`（Windows 上带
`.exe`）。托盘运行 `xiaozhi-tv-core selfhost --desktop`（不带参数也是这个意思），可以加 `--data <文件夹>`；不加时数据
目录是 5.5 节里各系统的那个。其他选项：`--ffmpeg <路径>`（或 `--ffmpeg fetch`：一定用固定哈希的下载版）、
`--bind 127.0.0.1`（只听本机；测试用）。从源代码运行时同一个核心是 `python3 -m server.selfhost --desktop`。

- **生命周期。** 启动时把标准输入设成一个托盘永远不写的管道，并设环境变量 `TV_WATCH_PARENT=1`：管道一关（托盘退出
  或被杀），核心就正常停止。Windows 上还要把它放进带 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` 的作业对象，并用
  `CREATE_NO_WINDOW` 启动；核心自己的每个子进程各在一个作业对象里，ffmpeg 孙进程跟着一起结束。
- **退出码。** 0 正常停止；1 起不来（原因在 `core.log` 和标准错误的最后几行）；3 这个数据目录上已经有一个核心在跑
  （`run/core.lock` 被占着）：改去读它的 `control.json`。核心不接受 `config.toml` 时不马上退出：控制接口照常开着，
  `state` 是 `error`，问题里有一条 `config` 说是哪一项，电视服务不启动；`stop` 之后退出码是 1。
- **Windows 上的窗口。** 核心启动的每个程序（一直到 ffmpeg）都带 `CREATE_NO_WINDOW`，不管谁启动核心都不会弹出控制台窗口。
- **同一个可执行文件的子命令**（内部用，给监督进程）：`__relay`、`__tv`、`__front`、`__channel-check`、`__selfhost`、
  `__tenancy-admin`（应急管理，`--db <数据目录>/tv.db`）、`__certs`。留给以后的阶段：`__gate`、`__worker`、`__hub-agent`、
  `__asr`。
- **锁。** 核心占着 `<数据目录>/run/core.lock`；托盘用自己的 `<数据目录>/run/tray.lock` 保证只开一个。

**`<数据目录>/run/control.json`**（接口开始监听后原子地写出，权限 0600，正常停止时删掉；崩溃留下的文件里的端口
已经没人应答）：

```json
{"api": 1, "port": 51234, "token": "<43 个字符>", "pid": 4242,
 "version": "0.2.0-beta", "started": 1760870000.0,
 "data_dir": "…", "logs_dir": "…"}
```

**请求。** `http://127.0.0.1:<端口>/local/v1/…`，请求头 `Authorization: Bearer <令牌>`。拒绝：没有令牌或令牌不对
（401）、`Host` 不是 `127.0.0.1:<端口>` 或 `localhost:<端口>`（403）、带任何 `Origin` 头（403；网页用不了这个接口）。
请求体是 JSON 对象，最多 64 kB。回答是 JSON：`{"ok": true, …}` 或 `{"ok": false, "error": "<代码>", "message":
"<给用户看的中文>"}`。

| 接口 | 请求体 | 回答 |
| --- | --- | --- |
| `GET /local/v1/status` | – | 下面的状态 |
| `POST /local/v1/console-link` | – | 还没有管理员时 `{"kind": "setup", "url": "http://localhost:<局域网端口>/tv/setup#<设置码>"}`（打开它，设置页里已经填好码）；有了之后 `{"kind": "login", "url": "http://localhost:<局域网端口>/tv/local-login?t=<令牌>", "expires_in": 60}`：在本机浏览器里打开就以管理员登录（30 天的电脑会话），落到 `/tv/console`。只能用一次，只认本机。网页前端起来之前 `503 not_ready` |
| `POST /local/v1/phone-qr` | – | `{"url": "HTTP://<局域网 IP>:<局域网端口>/TV/P/<令牌>", "svg": "<svg…>", "code": "<8 位码>", "typed": "http://<局域网 IP>:<局域网端口>/tv/p", "expires_in": 300}`：现有的一次性手机登录（以管理员；网址大写是为了二维码小；`code` 是手机在 `typed` 那一页输入的码）。10 分钟最多 6 个，再多 `429 limited`。`409 setup_pending`、`503 no_lan_address`（只听本机或不知道局域网地址）。`pairing_url` 等 P5 |
| `POST /local/v1/power` | `{"keep_awake": "watching" \| "always" \| "never"}` | `{"settings": {…}}`。只存下来；睡眠断言由谁来拿是 P2b 的事 |
| `POST /local/v1/autostart` | `{"enabled": true \| false}` | `{"settings": {…}}`。只存下来；登录项由托盘注册 |
| `POST /local/v1/network/trust` | `{"id": "<状态里的 network.id>", "trusted": true \| false}` | `{"network": {…}}`（5.11）：`true` 记下家里的网络（在那里开放端口），`false` 是「这不是我家的网络」（在那里不开放）。id 不是 16 位十六进制时 `400 bad_request`；核心不管网络时（`bind = "127.0.0.1"`、`config.toml` 不合法）`409 not_available` |
| `POST /local/v1/ffmpeg/fetch` | `{"mirror": "<基础网址>"}`（可选） | `202`，开始下载（ffmpeg 缺失或上次失败时）；否则 `409 busy` 或 `409 ready`。进度在状态里 |
| `POST /local/v1/diagnostics` | `{"dest_dir": "<文件夹>"}`（可选；默认桌面，没有桌面就 `<数据目录>/exports`） | `{"path": "<压缩包>", "size": n}`（5.15；不含秘密，地址截短） |
| `POST /local/v1/restart` | – | `202`；重读 `config.toml`（端口和 `bind` 除外）和局域网地址，再按它们重建所有子进程 |
| `POST /local/v1/stop` | – | `202`；核心停止，退出码 0 |
| `/local/v1/remote/*`、`/flash/*`、`/update/*` | – | `501 not_implemented`，等 P5、P7、P8 |

状态（`GET /local/v1/status`），每个字段都一定有：

```json
{"ok": true, "api": 1, "version": "0.2.0-beta", "pid": 4242, "started": 1760870000.0,
 "state": "starting | fetching_ffmpeg | running | stopping | error",
 "problems": [{"code": "…", "message": "…"}],
 "data_dir": "…", "logs_dir": "…", "bind": "0.0.0.0",
 "ports": {"lan": 8080, "lan_wanted": 8080, "xingzhi": 8098, "passport": 8097, "control": 51234},
 "lan_url": "http://192.168.1.5:8080/tv/", "local_url": "http://localhost:8080/tv/",
 "setup_pending": true,
 "children": {"relay": {"running": true, "restarts": 0}, "xingzhi": {…}, "passport": {…}, "front": {…}},
 "devices": [{"id": "…", "name": "…", "model": "xingzhi-cube-154", "online": true, "channel": "…", "since": 1760870100.0,
              "listening": false}],
 "watching": 1, "listening": 0,
 "network": {"id": "<16 位十六进制，或空>", "trusted": null, "profile": "", "lan_open": true},
 "ffmpeg": {"state": "ready | fetching | missing | failed", "path": "…", "source": "given | system | fetched",
            "done": 0, "total": 0, "error": ""},
 "voice": {"mode": "off"}, "hub": {"state": "off"}, "update": {"available": false},
 "settings": {"keep_awake": "watching", "autostart": true}}
```

`problems[].code` 是这几种之一：`ffmpeg_missing`、`ffmpeg_failed`、`port_in_use`（带 `port`；系统肯说时还带
`holder`：占着它的程序名）、`lan_port_moved`（带 `from` 和 `to`）、`child_down`（带 `name`）、`config`（config.toml
不合法；这时 `state` 是 `error`）、`network_away`（不在家里的网络上：局域网端口在 127.0.0.1）、`network_public`
（Windows：端口开着时网络被标成公用）。托盘显示第一个问题的 `message`。只听本机或不知道局域网地址时 `lan_url` 是空串。

托盘上的开关存在 `<数据目录>/desktop.json`（核心经接口写），不放进 `config.toml`：那是用户手改的文件，程序从不改写。

### 5.15 日志和诊断

- 监督进程把每个子进程带前缀的输出写进 `logs/core.log`，满 2 MB 轮转，留 5 个；托盘进程写 `logs/tray.log`。规则不变：
  不记令牌、密钥、会话 id、配对密钥和完整 IP 地址。

## 6. 局域网里的设备和手机

### 6.1 设备怎么找到电脑

| 方式 | 状态 | 说明 |
| --- | --- | --- |
| 手机**声波配网**，服务器一栏预先填好电脑的地址 | 能用（S1 把 `device_address` 注入 `wifi.html`） | 默认路径；电脑知道自己的局域网地址（不在容器里），所以没有桥接 Docker 横幅那个问题 |
| **内置刷机时写入地址** | Q9 B | 星智：擦除后写一个小 NVS 分区，里面是 `wifi/ota_url`（`tools/set_server_addr.py` 改的那一项）。Passport：从不擦除；只像 `set_server_addr.py` 那样改写已有的 `ota_url`，或者交给声波配网 |
| 热点页 `192.168.4.1` | 能用 | 后备，和现在一样 |
| 用电脑的 `.local` 名字代替 IP | 未验证 | DHCP 换了地址也不受影响；ESP-IDF 默认开着 lwIP 的 mDNS 查询，但两块板子都没测过；Windows 10 及以上和 macOS 会应答自己的名字。验证通过的话，客户端提议用 `.local` 名字作 `device_address` |
| UDP 发现后备（固件） | 以后 | 存的服务器连续 N 次不应答时，设备广播一个「电视服务器在哪」的数据包；客户端回答自己的地址；设备只接受中转公钥和它首次信任时记下的 `wifi_key` 一致的服务器的回答。固件约 1.5 个 agent-day，服务器 0.5 |

地址会变：笔记本的 DHCP 租约通常保持同一个 IP，但不保证。教程把 DHCP 保留地址作为可选建议；`.local` 名字或发现后备
可以免掉这一步。

### 6.2 手机怎么找到电脑

- **电脑上的二维码**：托盘 >「连接手机」打开一个页面，显示 `http://<局域网 IP>:<端口>/TV/P/<一次性手机链接>`（现有的
  「让另一部手机登录」，`server/tenancy/phonelinks.py`）。扫了就以这家的账号登录；「添加到主屏幕」照旧靠 `?s=`。
- **设备上的二维码**（`/TV/R/<码>`）继续给访客和家人用。
- 开了中继时，同一个页面还显示外出遥控的配对二维码（第 7.4 节）；按 Q4 A，家里人只加这一个。

### 6.3 多台同时看（gate-lite，S2）

家里一有两台同型号设备就需要。自建设计 5.3 节的设计不变（在 8097/8098 监听，读 HELLO，按 `model` 选参数，把套接字
交给这台设备自己的工作进程，工作进程留 10 分钟，`max_streams` 上限，未绑定的画面由网关自己发）。电脑上多出来的：

- **Windows 没有 `socket.send_fds`。** Windows 有自己的交接方式：网关里 `socket.share(工作进程 pid)`，工作进程里
  `socket.fromshare(data)`（底下是 WSADuplicateSocket）。网关经一条回环控制连接把这段数据和 HELLO 的字节交给工作
  进程。POSIX 继续经 Unix 套接字用 `send_fds`。
- **不做逐字节转发的代理。** 转发字节的网关更简单、也跨平台，但它会在工作进程和设备之间多出两个套接字缓冲，藏住
  发送端的节奏和码率控制器测量的背压。交接让工作进程直接用设备自己的套接字。
- **启动时间。** 设备等 CONFIG 只等 2 秒。Windows 上打包的 onedir 工作进程启动时，Defender 要扫一遍新进程（推算
  0.5–1.5 秒，待测）；网关在 Windows 上从一开始就给每个型号**预热一个备用工作进程**。
- 工作量：S2 的 3–4.5 天，加约 0.5–1 天做 Windows 路径和测试。

### 6.4 一家人的简化

和自建设计 7.3 一样（没有旧令牌、不迁移、设备名字更好懂），另外：电脑自己的浏览器经控制接口以管理员身份登录；
用户页保留（家人、访客），但电脑版打开时停在遥控页，不在管理页；经未绑定设备自己注册仍然只限局域网。多用户的代码
一行都不删：访客、家人账号和可选服务器都要用它。

## 7. 云端遥控通道（中继）

### 7.1 为什么自己做：和其他方案比较

| | **中继（本设计）** | 经你服务器的 frp | Tailscale / ZeroTier | Cloudflare Tunnel | 端口转发 + DDNS |
| --- | --- | --- | --- | --- | --- |
| 家里要装什么 | 客户端之外什么都不用 | 不用（frpc 在客户端里） | **每部手机**都要装 VPN 应用，还要一个账号（Google、GitHub、Microsoft） | 手机上不用；每家要在 Cloudflare 上有一个域名 | 不用；要能进路由器 |
| 没有公网 IP 能用吗 | 能（出站 443） | 能 | 能，常常经它们的中继 | 能 | 不能（国内家庭宽带现在普遍是运营商级 NAT） |
| 什么经过你的服务器 | 加密的小 API 调用 | 代理的一切：网页、用手机听的音频、这家打开的任何东西 | 不经过（走它们的中继） | 不经过（走 Cloudflare） | 不经过 |
| 你看得到内容吗 | 看不到（端到端加密） | 看得到，除非每家自己再加 TLS | 看不到 | 看不到（Cloudflare 看得到） | 看不到 |
| 中国大陆 | 国内主机，快 | 快 | 中继在海外，慢，部分网络受干扰 | 免费版在大陆没有节点；慢 | 80/443 端口通常被封 |
| 手机上的 HTTPS（扫码、复制、锁屏控制） | 有，公开域名 | 每家都要自己的证书才有 | 有（`ts.net`） | 有 | 要自己弄证书 |
| 我们的工作量 | 7–9.5 个 agent-day | 2–3 天，之后要管一条通用隧道 | 只写教程 | 只写教程 | 只写教程 |
| 被滥用的面 | 固定的 API 形状、配额、不转发各家的 HTML | 你域名上的一条通用 TCP/HTTP 隧道：钓鱼页、代理 | 与我们无关 | 与我们无关 | 每家自己的暴露 |

只有中继这一个方案不要求不懂技术的家庭做任何事、能穿过运营商级 NAT、在国内快，而且你的服务器既看不到也不承载内容。
其他方案作为 Docker 和 NAS 用户的**进阶做法**保留（自建教程里的那几页）。

### 7.2 电脑和中继之间的协议

- **传输：** 电脑上的中继代理建一条到 `wss://<public-domain>/hub/v1/pc` 的 TLS WebSocket。nginx 终结 TLS，把升级请求
  转给本机回环上的中继。用标准库写一个最小的 RFC 6455 实现（文本和二进制帧、ping/pong、关闭；不支持扩展），中继和
  代理共用，带测试约 300 行，`server/` 继续不依赖第三方包。
- **认证：** 升级后代理发
  `{"t":"hello","hh":"<家庭 id>","token":"<家庭令牌>","core":"<版本>","pages":"<页面版本>"}`。
  中继只存令牌的 SHA-256（和中转存会话的方式一样）。令牌不对就带错误码关闭，按 IP 计数。
- **心跳：** 代理每 45 秒发一次 ping（远在家用路由器和运营商级 NAT 的空闲超时之内；要在几个国内网络上验证）；中继
  120 秒没动静就断开。nginx 的 `proxy_read_timeout` 设得比这更长。
- **重连：** 指数退避，1 秒到 60 秒，全随机抖动；中继重启后第一次重试分散在 0–30 秒内，一千台电脑不会在同一秒里重连。
  同一家的新连接替换旧连接。
- **帧：** 中继发 `{"t":"call","id":<n>,"phone":"<手机 id>","env":"<密文>"}`，代理回
  `{"t":"reply","id":<n>,"env":"<密文>"}`；另有代理发的 `{"t":"block","phone":…}`（不再转发认证失败的手机）和中继发的
  `{"t":"quota",…}`（告诉电脑它正被限流）。

### 7.3 手机到中继

- `GET /r/`（静态，nginx 直接给）：一个很小的引导页。它从网址片段或自己的存储里读配对信息，问
  `GET /hub/v1/h/<hh>/info`（在不在线、从什么时候起、页面版本），然后加载 `/r/v/<页面版本>/remote.html`。
- `POST /hub/v1/h/<hh>/call`，内容 `{"phone":"<手机 id>","env":"<密文>"}`：中继把它转到这一家的连接上，等回复（20 秒；
  电脑版登录的长轮询给 30 秒），再把密文回给手机。电脑不在线：`503 {"pc":"offline","since":…}`；超配额：`429`。
- 每个遥控 API 调用一个 HTTPS 请求；nginx 和手机之间保持 HTTP/2 连接，所以每次调用的开销是几百字节的请求头。
- **网页是静态的、按版本放。** 发布流程把遥控页和电脑版页面打成 `remote-pages-<版本>.zip`；你部署时解到
  `/r/v/<版本>/`，留最近十个版本。电脑在 `hello` 里报自己的页面版本，所以手机拿到的页面总和它那台电脑的接口对得上。
  不认识的版本（开发版）得到「请更新电脑客户端」，而不是一个对不上的页面。
- **网页的改动很小。** `remote.html`（约 40 处）和 `console.html`（约 34 处）的每个 API 调用都经过同一个 `call()`，
  里面就是 `fetch(path)`。中继模式下 `call()` 先加密、发给中继、再解密；页面其余部分不变。中继模式下「用手机听」按钮
  显示「只能在家用」（Q3）。

### 7.4 配对

```
开启（每台电脑一次）                             配对一部手机
托盘/电脑版「在外面遥控」                          托盘「连接手机」，或局域网遥控页上的
  电脑 ─POST /hub/v1/register {邀请码}─► 中继      「在外面也用这部手机」
  中继 ─► {hh：26 个字符的 id，令牌}               核心：phone_id（随机 64 位）、K（256 位），
  存进 secrets/hub.json（0600）                     给选中的用户新建一个中转的手机会话，
  代理连上                                          存成 pairs[phone_id] = {K, 会话, 用户}
                                                 二维码/链接：https://<public-domain>/r/#p1.<hh>.<phone_id>.<K>
                                                 手机打开 ─► 引导页把 (hh, phone_id, K) 存进自己的存储，
                                                   并把片段留在地址里，方便「添加到主屏幕」
```

- **密钥放在网址片段里**，浏览器从不把片段发给服务器；中继看不到它。二维码显示在电脑屏幕上（托盘），或者由手机自己
  在局域网遥控页上生成：那是从局域网页面跳到公开页面的一次导航（局域网页面经片段把它带过去）。
- **手机上只有一个秘密。** 手机拿着 `K` 和自己的 `phone_id`；电脑保存对应的中转会话，转发每个请求时加上。这样中转现有
  的账号检查原样适用，撤销一次配对就撤销了那个会话。
- **主屏幕应用**在 iPhone 上和 Safari 的存储是分开的；现有遥控页靠保存的地址里带 `?s=` 解决这个问题。引导页出于同样的
  原因在「添加到主屏幕」之前把配对片段留在地址里（iOS 是否把片段保存在主屏幕书签里，要在真机上验证）。
- **撤销：** 电脑版的设置里列出「在外面用的手机」（名字、何时配对、最后使用）并可撤销；托盘「忘掉所有手机」同时轮换
  家庭令牌。180 天没用的配对过期，和手机会话一样。

### 7.5 中继上的路由，以及电脑怎么处理一次调用

```
手机 ─HTTPS─► nginx ─► 中继：按 hh 找到连接；查配额；转发 {id, phone, env}
                               │
电脑上的中继代理 ◄─WSS──────────┘
  用 pairs[phone].K 解密（失败 → 计数，10 次后封掉）
  查允许清单；加上 Cookie: tvs=<pairs[phone].会话>
  HTTP 发到前端的隧道端口 127.0.0.1:<隧道端口>（X-Forwarded-For：中继给的手机网段）
  响应 → gzip → 加密 → 回复
```

- 前端多一个监听：**隧道端口**，绑在回环上，只给代理用。它沿用现有公开端口的规则（没有总后台、没有第一次设置、没有
  `?k=`、不能自己注册），另加一张遥控和电脑版 API 路径的**允许清单**；其他一切（刷机页、「用手机听」的流、播放列表
  导入、帮助页）都拒绝。
- 中继在内存里维护 `hh → 连接` 和 `id → 等待中的手机请求`；调用的内容一概不存。一张小 SQLite 表存家庭（`id`、令牌
  哈希、创建时间、最后在线、状态、用掉的邀请码、配额计数）。

### 7.6 端到端加密

对称加密，密钥来自配对，所以不需要浏览器或 Python 缺的任何东西：

- 配对共享 `K`（256 位）。每个方向一把：
  `k_up = HKDF-SHA256(K, salt = "tvhub1" ‖ hh ‖ phone_id, info = "phone→pc")`，
  `k_down` 同理，info 是 `"pc→phone"`。
- 每条消息：AES-256-GCM，96 位随机 nonce，AAD = `hh ‖ phone_id ‖ 方向`。明文：`{"ts": <毫秒>, "rid": <随机数>,
  "m": "GET", "p": "/api/state", "b": …}`；响应 `{"rid": …, "st": 200, "ct": "application/json", "b": <gzip+base64
  或原样>}`。
- **防重放：** 电脑拒绝 `ts` 和自己时钟相差超过 ±120 秒的消息（手机从每次回复里学到电脑的时钟偏差），记住 240 秒内
  见过的 `rid`。
- **浏览器：** WebCrypto（`crypto.subtle`：HKDF、AES-GCM），所有当前浏览器在安全上下文里都有，包括微信内置浏览器；
  公开页面是 HTTPS，所以是安全上下文。
- **Python：** 客户端随包带 `cryptography`（快，底下是 OpenSSL）；没有它时（直接用 Python 跑），核心退回到给 Wi-Fi
  加密已经写好并测过的 AES-GCM 和 HKDF（`server/wifi_crypto.py`），慢，但每几秒几 KB 足够了。两边共用一组测试向量，
  和 `tests/test_wifi_crypto.py` 一样。
- **先压缩再加密**，让中继的流量小（状态 JSON 能压缩好几倍）。常说的压缩旁路问题，要攻击者能把自己选的文字和秘密
  放进同一条消息、再观察大小；这里的响应不会把秘密和攻击者可控的文字混在一起（会话令牌由电脑添加，从不返回）。
  接受，记录在案。
- **没有前向保密：** 以后拿到 `K` 的人能解开这部手机被录下来的流量。等家庭们用的手机都支持 WebCrypto X25519（iOS 17
  及以上、较新的 Chrome），以后的版本可以加一次 X25519 交换。
- **局限，在隐私说明页上明白写出：** 页面的 JavaScript 由你的服务器提供。端到端加密让服务器的日志、数据库和运维人员
  看不到内容；防不了一台故意下发恶意页面的服务器。页面是开源的，每个版本都列出它们的哈希。

工作量：2.5–3.5 个 agent-day（两边、测试向量、重放窗口）。好处：中继从不经手会话令牌、发给设备的 Wi-Fi 密码、片名或
订阅；中继被攻破也只泄露路由 id。

### 7.7 什么经过中继，什么永远不经过

| 经过中继 | 永远不经过 |
| --- | --- |
| 遥控和电脑版的 API 调用（状态、换台、拖进度、暂停、音量、投一个链接、UP 主、剧集、历史、设备设置、设备的 Wi-Fi 管理） | 发给设备的视频（原始 TCP 留在局域网） |
| 电脑版扫码登录的长轮询（如果在外面用电脑版） | 用手机听的音频（Q3：只在局域网） |
| | 总后台、第一次设置、应急的密钥链接 |
| | 固件、刷机页、播放列表导入、ffmpeg、模型下载 |
| | 任何形式的设备连接 |

遥控页面本身来自中继的静态文件夹，不来自电脑。

### 7.8 故障情况

| 故障 | 影响 | 处理 |
| --- | --- | --- |
| 中继或你的服务器挂了 | 在外面遥控用不了 | 局域网不受影响：设备、局域网遥控、电脑版照常。公开页面说「连不上中继服务」 |
| 电脑睡着、关机或断网 | 中继回答「电脑自某时起不在线」 | 页面如实说；Q8 的不睡眠选项给想要的家庭 |
| 中继重启 | 所有电脑重连 | 带抖动的退避；手机 2 秒后重试一次 |
| 版本对不上 | 不认识的页面版本 | 「请更新电脑客户端」 |
| 电脑重装、数据目录没了 | 旧的家庭令牌没了 | 重新开启：新的家庭，手机重新配对；旧的家庭 30 天不见就过期 |
| 配对密钥泄露 | 别人能遥控这一家 | 撤销那部手机；「忘掉所有手机」全部轮换 |
| 中继配额用完 | `429` | 页面放慢；电脑托盘上显示 |

### 7.9 限流、配额、防滥用

- 每家：8 部配对手机，每分钟 120 次调用，每天 30 MB，每条消息压缩后最大 256 kB；超出时中继回 `429`。
- 每个手机网段：跨家庭每分钟 60 次调用（防一部手机挨个试很多家庭 id）。
- 注册：测试版凭邀请码（Q2）；之后每个网段每天 3 家，另有全局上限，你的总后台里每家都有一个停用开关（新增「家庭」
  列表：id 前缀、创建时间、最后在线、在不在线、今天的调用次数、今天的字节数、状态；从不显示内容）。
- **带宽保护：** 中继按秒统计自己的出站字节；超过 3 Mbit/s 里给它的份额（默认 1 Mbit/s）时，先让页面放慢轮询（5 秒变
  15 秒），再考虑拒绝，这样你自己和可选用户的视频流优先。
- 中继不提供任何来自各家的 HTML，只把固定形状的信封转给一台电脑，所以既挂不了钓鱼页，也当不了通用代理；配额让它没法
  被当作隐蔽通道。
- 电脑丢弃解不开的调用，10 次失败后请中继封掉那个手机 id。

### 7.10 每家的成本和现在这台主机的容量

**推算**，P5 阶段用模拟家庭实测：

| 项目 | 每家 | 说明 |
| --- | --- | --- |
| 空闲连接的内存 | 约 100 kB（中继的协程和缓冲 10–20 kB，nginx 的 TLS 连接和上游连接 50–80 kB） | asyncio，所有连接一个线程 |
| 空闲流量 | 每 45 秒一次 ping：约 4 B/s，每月约 10 MB | 大部分是入站 |
| 一部在前台的遥控手机 | 每 5 秒取一次状态：压缩后 1–4 kB，没变化时约 0.3 kB（电脑按哈希回答「和上次一样」）：出站 **0.1–0.8 kB/s** | 页面隐藏或锁屏时停止轮询 |
| 一条命令（换台、暂停） | 来回 1–3 kB | |
| 静态页面 | 第一次加载压缩后 30–60 kB，之后走缓存 | `remote.html` 未压缩约 100 kB |

现在这台主机的容量（2 vCPU，可用约 1.8 GB，其中 `muse-asr`、中转和媒体服务已经占了大部分；出网 3 Mbit/s）：

| 限制 | 给中继的预算 | 家庭数 |
| --- | --- | --- |
| 内存 | 150–250 MB | 约 1,500–2,500 个已连接 |
| 文件描述符 | 调高 nginx 的 `worker_connections` 和 `nofile`（nginx 上每家两个描述符） | 是配置问题，不是上限 |
| 出网带宽 | 带宽保护给的 1 Mbit/s（125 kB/s） | 同时约 150–1,000 部**在前台**的遥控手机，取决于状态变化多频繁 |
| CPU | 转发消息几乎不花 CPU；重启后的 TLS 握手每次约 1 ms | 几千，配抖动 |

所以「几百到几千个家庭」对**已连接**的家庭成立；真正的上限是同一时刻有多少部手机在前台，而这个数很小，因为人们用遥控
都是一阵一阵的，而且大多在家。真增长了，就把中继单独搬到按流量计费的实例上（Q11）；总流量不大（推算 1,000 家每月
10–30 GB），紧的是 3 Mbit/s 的峰值。

### 7.11 现在不选：点对点

手机和电脑之间用 WebRTC 数据通道、中继只做信令，在 NAT 允许时（不用 TURN 时推算 70–85 % 的情况）连这点 API 流量
都不经过你的服务器。代价是电脑客户端要带一套 WebRTC（很大的原生依赖），而且后备路径还是要中继。等中继流量真成了
瓶颈再议。

## 8. 可选服务器账号

给没有电脑的人，你的主机保留多用户中转和媒体服务。新增：每个用户可以有有效期和限额。

### 8.1 数据和执行

`user` 表加几列（按现有方式，在 `server/tenancy/db.py` 里 `ALTER TABLE … ADD COLUMN`）：`valid_from REAL NULL`、
`valid_until REAL NULL`、`max_devices INT NULL`、`max_streams INT NULL`、`note TEXT`。NULL 表示不限；管理员和现有用户
保持不限。邀请带上新用户的默认值（Q10：1 台设备、1 路、3 个月）。

| 在哪 | 检查 |
| --- | --- |
| 解析会话（`server/relay/web.py`、账号） | 不在 `[valid_from, valid_until)` 内：当作停用；页面显示「使用权已于某日结束」或「某日开始」 |
| 设备 HELLO（`server/tenancy/gate.py` 的 `apply()`） | 主人不在有效期内：CONFIG 加一张静止画面（和未绑定画面一样），不转码 |
| 同时几路 | 数这个用户此刻在线的设备（新鲜的 `devices/<id>/now-playing.json`）；超过 `max_streams` 回 `ERROR {"reason":"server busy"}`；有了阶段 4 网关后挪进准入控制 |
| 绑定 | 超过 `max_devices` 拒绝新的绑定，给出清楚的提示 |
| 中转里每天一次的巡查 | 到期：结束这个用户的会话，踢掉他的设备（`_kick`），记审计 `user.expired`；到期前 7 天：在遥控页上提醒 |

### 8.2 总后台

用户页（`server/relay/admin.py`、`assets/admin.html`）加几列：「有效期至」、「设备 x/上限」、「路数上限」，一个状态标记
（正常、未开始、已到期、已封禁），快捷操作「延长 1 个月 / 3 个月 / 1 年」，一个编辑这四项的对话框，以及筛选「7 天内
到期」。每次改动都记审计。概览页在主机曲线旁边显示中继的家庭数和带宽。

### 8.3 他们的设备，以及实话实说的容量

这类用户的设备连 `<public-domain>`（8098/8097 端口），和现在一样，手机用 `https://<public-domain>/tv/`。主机的
3 Mbit/s **总共**只能扛一台全画质的星智，或者两台都降画质，由你和所有开通的用户共用（多用户设计 7.6）。没有阶段 4
网关时，每个型号同一时刻还只有一条连接：别人的星智在播时，任何地方的第二台星智都会显示「服务器没有应答」。纯音频约
0.07 Mbit/s。所以：只开通给少数几个看电视时间很少重叠的人，`max_streams = 1`；阶段 4 网关（带管理员优先）只有和带宽
升级一起做才值得。

内容：可选服务器把你的频道表放给你开通的人，这是你在给别人提供内容；多用户设计里「只限家人朋友、凭邀请」的规则不变。

## 9. 内容和版权

和自建设计第 8 节一样：客户端不带频道表、直播地址、cookies、代理；第一次运行从空开始，靠导入播放列表；YouTube 是
一个通用的节点或代理设置，不提供获取方法。中继不走内容，有了端到端加密也看不到片名。免责声明为遥控通道加一句：
「在外面遥控时，加密的命令经过项目的中继服务，中继无法读取，也不传输任何视频或音频。」

## 10. 安全

| 话题 | 设计 |
| --- | --- |
| 局域网暴露 | 客户端在局域网上监听：8080（网页）、8097、8098（设备）。Windows 防火墙规则只对专用网络；在别的网络上，受信任网络功能把它们绑到回环（5.11）。其他一切（中转、「用手机听」、隧道端口、控制接口、语音识别）都只在回环 |
| 本机控制接口 | 回环、随机端口、每个用户文件里的随机令牌；一次性电脑版链接 60 秒过期 |
| 第一个管理员 | S1 的设置码，经片段交给本机浏览器 |
| 远程路径 | 只有代理能到隧道端口；公开端口规则加允许清单；没有总后台、第一次设置、密钥链接、刷机页、「用手机听」 |
| 配对密钥 | 每部手机一个 256 位 `K`，只在片段里；在电脑上存于 `secrets/`（0600 或用户权限）；可撤销；180 天不用就过期 |
| 家庭令牌 | 256 位，中继上存哈希；「忘掉所有手机」时轮换 |
| 你的服务器作为中继 | 看得到家庭 id、手机 id、IP 地址、时间和大小；看不到内容（端到端加密）。不记调用日志，只记计数；带 id 的 `/hub/` 和 `/r/` 路径关掉访问日志 |
| 设备连接 | 不变：局域网上的明文 TCP，每台设备自己的密钥 |
| 更新 | HTTPS 下载，SHA-256 来自一份用离线 Ed25519 私钥签名的清单，用户确认后才安装；从不静默运行 |
| 下载的组件 | ffmpeg、esptool、语音运行库和模型：版本和 SHA-256 写死，不符就拒绝（`ffmpeg_fetch` 的规则） |
| 不签名的程序 | 测试版期间用户被教着绕过系统警告；靠发布签过名的校验值缓解，正式发布前签名 |
| 可选服务器 | 和多用户设计一样，加上有效期和限额（第 8 节） |

## 13. 分阶段计划

工作量以 agent-day 计（一个 agent 加主机测试），不含你的审阅和真机检查。在你的机器上只做轻量的工作；除了 P5e 里那个
小规模模拟，不做压测。

### P0 —— 决定和小试验（1–1.5）

回答 Q1–Q15。小试验：pystray 在 PyInstaller onedir `.app` 里和 Windows 上能不能用；打包后的子命令分派配合监督进程；
Windows 上 `socket.share` 交接；典型家庭的 `/api/state` 有多大；iOS 主屏幕书签保不保留网址片段。

### P1 —— 核心打包，三个系统（3–4）

- P1a. 打包分派、spec（`server.relay`、`server.tenancy`、`server.selfhost`、`server.front`、`server.listen` 的隐式导入；
  网页、刷机页和帮助页作为数据），每个子进程的冒烟测试。（1–1.5）
- P1b. 监督进程的 Windows 路径：作业对象、不靠信号的停止、语音识别走 TCP、非 ASCII 路径、端口后备、`%LOCALAPPDATA%`。
  （1–1.5）
- P1c. 控制接口、一次性电脑版链接、轮转日志、诊断信息。（1）

**P1 的状态（2026-10-19，分支 `desktop-core`）：已实现。** 约定见 5.13 节「实际实现的约定」。文件：
`server/selfhost/desktop_main.py`、`desktop.py`、`control.py`、`diagnostics.py`、`supervisor.py`（`child_command`、每个子进程
一个作业对象或进程组）、`server/relay/setup.py`（`/local-login`）、`tools/core_entry.py`、`tools/packaged_entry.py`
（`run_core`）、`packaging/desktop/xiaozhi-tv-core.spec`、`tools/build_core.py`、`tools/smoke_test_core.py`、
`.github/workflows/build-desktop-core.yml`，测试在 `tests/test_selfhost_desktop.py`。验证过：打包的 onedir 核心通过
`tools/smoke_test_core.py`（每个子命令、路径带中文和空格的数据目录、ffmpeg 下载、控制接口的拒绝和回答、第一次设置、一次性

## 14. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 杀毒软件误报 PyInstaller 构建 | 装不上，或核心被删 | onedir、从源码编引导程序、提交误报、正式发布前签名 |
| 用户过不了 Gatekeeper 或 SmartScreen | 测试版卡在安装 | 带截图的教程；正式版签名（Q13） |
| Windows 上家里的 Wi-Fi 被标成公用 | 设备连不上 | 托盘里检测并说明（5.11） |
| 电脑睡了或关了 | 设备显示「服务器没有应答」；遥控说电脑不在线 | 不睡眠选项；清楚的提示；以后做网络唤醒 |
| 电脑的 IP 变了 | 设备找不到服务器 | 验证后用 `.local` 名字；以后做发现后备；可选 DHCP 保留 |
| 中继用的人多了 | 你的 3 Mbit/s 或内存被占满 | 带宽保护、配额、测试版凭邀请、把中继搬到单独的实例（Q11） |
| 手机上的端到端密钥（存储被清、主屏幕存储分开） | 手机要重新配对 | 配对就是扫一下；局域网遥控页能自己重新配对 |
| JavaScript 由你的服务器提供 | 端到端加密防不了恶意服务器 | 在隐私说明里写明；每个版本列出页面哈希 |
| 国内访问 GitHub 和 PyPI | 下载、ffmpeg 下载、更新失败 | 安装包的国内镜像；1.0 随包带 LGPL ffmpeg；固定哈希的镜像 |
| ffmpeg / esptool / pystray 的许可证 | 合规 | 带源码的 LGPL 构建；esptool 作为独立程序、附源码链接；NOTICE |
| macOS 的 App Nap 或电源管理给核心降速 | 后台卡顿 | `NSAppSleepDisabled`，看的时候持有电源断言；在 macOS 14/15 上验证 |
| Windows 上工作进程启动超过 2 秒 | 空闲后的第一次连接失败 | 每个型号预热一个备用工作进程（6.3） |
| 客户端、Docker、云端之间走样 | 一个核心三种跑法 | `--desktop` 只是配置；CI 对三者跑同一套测试 |
| 可选服务器的内容 | 你在给别人提供内容 | 只给少数受邀的人，和多用户设计的决定一样 |

## 15. 未验证

- 所有标了**推算**的数字：中继每个连接的内存、状态大小、Windows 上工作进程的启动时间。
- pystray 在 macOS 14/15 上 PyInstaller 打的 `.app` 里能否工作，以及它在 GNOME 上的托盘支持。
- Windows 上打包进程之间 `socket.share`/`fromshare` 的交接。
- 国内家用路由器和运营商级 NAT 对 45 秒心跳的空闲超时。
- iOS 是否在主屏幕书签里保留网址片段；当前 Android 和 iOS 上微信浏览器里的 WebCrypto HKDF 和 AES-GCM。
- 设备能否解析 `.local` 名字（两块板子）；默认防火墙规则下 Windows 是否为自己的主机名应答 mDNS。
- 未签名的菜单栏应用在 macOS 15 上「本地网络」询问的表现；`NSAppSleepDisabled` 对核心的子进程是否生效。
- 构建时 GitHub 上是否还有 Intel 的 macOS 构建机；中国大陆能否用 Azure Trusted Signing；Apple 和证书的当前价格。
- 在 macOS 上用 SecureTransport TLS 编的最小 LGPL ffmpeg 能否覆盖家庭们用的片源。
- SenseVoice-Small 的许可证是否允许由客户端下载。
