# 接入其他网站的视频 —— 设计

状态：2026-11-05 主人逐段确认。这里设计的是 A 部分（经 yt-dlp 接入任意网站）；B 部分（登录后的腾讯视频、优酷、爱奇艺、芒果 TV）先实测 DRM，再单独写设计。

## 1. 目标和边界

主人想要 B 站、YouTube、片库之外更多的来源：粘贴任意视频网址，在电脑或小电视上放；订阅任意网站的作者或播放列表；能搜的网站可以搜。

- 只接 yt-dlp 有**专门解析器**的普通视频网页。yt-dlp 的 `generic` 解析器（随便抓网页里的视频）一律拒绝。
- **不做资源站聚合。**「苹果CMS 采集接口」（`/api.php/provide/vod`，LibreTV 聚合的那种）放的是盗版影视，现在和以后都不支持、不内置。
- **不破解 DRM。** yt-dlp 说有 DRM 加密的视频，就照实显示，不重试。
- cookies 属于这台服务器，由管理员按站导入（cookies.txt），从不读主人浏览器里的登录。
- 只给家人，访客看不到（和片库一样）。只在家庭服务器和电脑客户端、YouTube 本机模式下有；精简版隐藏这一页。

做法：扩展现有的本机 yt-dlp 节点（`server/relay/ytnode.py`），不在中转里另外调用 yt-dlp，也不把它嵌进中转。节点已经管着安装和自动更新、解析缓存、起播优先、电视的小码流 TS 和电脑的格式列表。

## 2. 节点：按网址的路径（`ytnode.py`，只在本机模式）

| 路径 | 回答 |
|---|---|
| `GET /web/info?url=` | 一个视频：标题、时长、封面、作者、所属站（`extractor_key`）。作者主页、播放列表回答 `kind: "list"` 和它的标题。 |
| `GET /web/list?url=&n=&start=` | 作者主页或播放列表最新的 N 个视频，能翻页。 |
| `GET /web/search?site=&q=&n=` | 只对 yt-dlp 能搜的站：B 站（`bilisearch`）、Dailymotion（`dmsearch`）、niconico（`nicosearch`）、SoundCloud（`scsearch`）。 |
| `GET /web/formats?url=` | 电脑用：全部格式和各自的 http 头，同 `/yt/formats`。 |
| `GET /web/stream?url=&ss=` | 电视用：和 `/yt/stream` 一样的小码流 MPEG-TS。 |

- 按域名找每个站的设置：cookies 在 `web-cookies/<域名>.txt`，代理二选一（直连（默认）或 YouTube 的代理）。
- 网址：只收 http/https；拒绝本机、内网、链路本地地址和 `file:`；日志里只记域名，不记完整网址和媒体地址。
- 解析缓存、起播优先、yt-dlp 自动更新都和 YouTube 共用。

## 3. 中转（`server/relay/websites.py`）

- `Relay.clients` 里加 `"web"`，接口和 YouTube 客户端一样（`video`、`open`、`formats`、`creator`、`series`、`search`）。视频 id 是规范化后的网址，`site="web"`，投屏、续播、继续观看、台都不用改。
- 订阅作者主页 → UP 主台（`kind="up"`）；订阅播放列表 → 剧集台。都受现有台数上限和小电视设置包大小的限制。
- 首页：每个订阅的作者一行，每 2 小时刷新；综合搜索也搜这些标题。
- 电脑上按格式选播放器：H.264 + AAC 的单个 MP4 → 中转转发给 `VodPlayer`（倍速、拖动）；带分段索引的 DASH → `DashPlayer`；其他（HLS、FLV、HEVC……）→ ffmpeg 转封装给 `WatchPlayer`；电视 → `/web/stream`。
- cookies（管理员，设置 → 网站）：按站上传，权限 600，不回传、不进日志；页面只显示有没有、几条、导入时间。

## 4. 页面和电视

- 顶栏**网站**（`data-route="web"`）：
  - 粘贴框（视频 → 卡片，「在这台电脑上放」/「放到小电视」；列表 → 它的视频和「订阅」，再问「加到电视」）；
  - 搜索（站点选择：「我订阅的」搜已拉下来的标题，或选一个能搜的站；滚动加载）；
  - 「我的订阅」（站名小标、最近更新、刷新、加到电视 / 拿下来、取消订阅）。
- 首页的行排在 YouTube 那几行后面，可以关；综合搜索里多一个「网站」分组。
- 设置 → 网站（管理员）：每个站的 cookies 状态和代理，导入、删除、「测试」（用这个站的 cookies 解析一个给定网址）。
- 小电视固件不改：网站台就是普通的 UP 主台、剧集台，从 `/web/stream` 取流。

## 5. 出错和测试

| 情况 | 页面上的话 |
|---|---|
| 要登录、cookies 过期 | 这个站要登录：在 设置 → 网站 导入 cookies |
| DRM | 这个视频有版权加密（DRM），放不了（不重试、不绕过） |
| 不支持、只有 `generic` 能认 | 这个网址不支持 |
| 地区限制、会员专享 | 照实说 |
| 解析器坏了 | 触发 yt-dlp 自动更新，「解析器在更新，稍后再试」 |
| 订阅某次刷新失败 | 留着上次的列表，那一行标「上次更新失败」 |

测试：节点的网址校验、域名 → 设置、参数；中转用 `FakeWeb` 客户端（成台、首页行、选播放器、错误归类）；`tests/console_web_test.mjs` 测页面的纯函数；在主人 Chrome 的测试页（静音）里用公开免费视频（央视、Dailymotion、B 站）实测。真电视上的播放留给主人。

## 6. 交付

| 步骤 | 内容 |
|---|---|
| A1 | 节点 `/web/*`；粘贴网址在电脑上放、投到小电视；设置 → 网站的 cookies |
| A2 | 订阅 → 首页行、电视台、后台刷新 |
| A3 | 单站搜索、「我订阅的」搜索、综合搜索的分组 |
| B | 腾讯视频、优酷等：先实测 DRM，再单独设计 |
