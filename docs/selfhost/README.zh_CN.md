# 在家里跑小智电视服务器（0.x 测试版）

> **进阶。** 家里是 Windows 电脑或 Mac 的，请用**电脑客户端**：有安装包、托盘图标，设置页自己打开
> （[`docs/desktop/`](../desktop/README.zh_CN.md)，0.2.0 测试版起）。这一页给 NAS、没有桌面的迷你主机、Docker、
> 或者从源代码运行的人。

小智电视的服务器可以装在你家里一台一直开着的电脑、NAS 或迷你主机上，小电视在同一个家庭网络里连它。不用云服务器、
不花带宽费，画面也最好。这一页是快速上手；设计和取舍见
[`2026-10-15-self-hosting-design.zh_CN.md`](../superpowers/specs/2026-10-15-self-hosting-design.zh_CN.md)。

**这个软件不带任何频道、直播流、播放列表、账号或 cookies。** 第一次启动时频道表是空的，要播什么由你自己添加
（「频道表」页可以按链接读几个网上公开的第三方播放列表，见第三步）。
请先读最后的[免责声明](#免责声明)。

## 测试版的限制

- **每个型号一次只服务一台小电视。** 家里有两台星智 Cube 时，第二台会显示「服务器没有回应」并自己重试，等第一台关掉或
  断开后才连得上。一台星智加一台 AI Passport 可以同时看。几台同时看要等 1.0 版。
- 还没有语音控制容器（以后的版本）。
- 打了「未验证」的步骤是照官方文档写的，作者还没有亲手试过；目前只在一台 Apple 芯片的 Mac 上不用 Docker 跑通过。

## 你需要什么

- 一台小智电视：星智 Cube 1.54（小智 AI 外壳）或 FoloToy AI Passport，刷上小智电视的公开固件。
- 一台一直开着的机器（下表），接在家里的网络上，最好在路由器里给它固定一个 IP（「DHCP 静态分配」）。
- 一根能传数据的 USB 线，和一台装了 Chrome 或 Edge 的电脑（刷固件时用一次）。
- 家里的 2.4 GHz Wi-Fi。

### 机器要多强

测试版每个型号一次只放一路，所以几乎任何能跑 Docker 的 64 位机器都够：内存至少 2 GB。下面是以后几台同时看时的参考，
除了标「实测」的，都是**估计**（按单核性能折算，还没在那种机器上测过）。

| 项目 | 数值 |
| --- | --- |
| 每路视频的 CPU | 实测（M1 Pro）：约 0.15 个核心（720p 片源；360p 约 0.07–0.09，1080p 约 0.18） |
| 每路视频的内存 | 实测：50–70 MB |
| 服务器空闲时 | 中转实测约 22 MB；其余进程预计合起来不到 100 MB |
| 每路的局域网带宽 | 实测：星智约 1.7 Mbit/s，AI Passport 1.0–1.2 Mbit/s |
| 每路从互联网下载 | 片源自己的码率，一般 1–6 Mbit/s |

| 机器 | 同时几路（估计） | 说明 |
| --- | --- | --- |
| Intel N100 / N97 迷你主机，8 GB | 约 10 | 推荐：待机 6–10 W |
| 旧笔记本，四代酷睿 i5 或更新，4 GB 以上 | 3–4（双核）到 6 以上（四核） | 合上盖子也不能睡眠 |
| Apple 芯片的 Mac | M1 Pro 约 30（还没测满） | 不能睡眠 |
| 群晖、威联通 x86 NAS（J4125、R1600） | 约 4–6 | |
| 绿联 DXP（N100） | 约 10 | |
| 树莓派 5，4–8 GB，64 位系统 | 约 6 | 实验性，没测过 |
| 树莓派 4，4 GB 以上，64 位系统 | 约 2 | 实验性，没测过 |
| ARM 的 NAS（Realtek RTD1296/1619B） | 0–1 | 不推荐 |
| 树莓派 3、Zero 2、32 位系统、路由器 | — | 不支持 |

## 第一步：装服务器

服务器用到这几个端口：**8080**（手机和电脑打开的网页）、**8098**（星智 Cube）、**8097**（AI Passport）。

### A. Mac 或 Linux，不用 Docker

已在作者的 Mac（Apple 芯片，Python 3.12，Homebrew 的 ffmpeg）上验证过。需要 Python 3.11 以上和 ffmpeg：

```bash
brew install python@3.12 ffmpeg          # Mac；Debian/Ubuntu：sudo apt install python3 ffmpeg git
git clone https://github.com/rooma1989/ai-passport-tv.git
cd ai-passport-tv
./run.sh --selfhost
```

数据（数据库、密钥、你的频道表）放在 Mac 的 `~/Library/Application Support/ai-passport-tv/selfhost`，Linux 的
`~/.local/share/ai-passport-tv/selfhost`；想放别处就加 `--data <文件夹>`。关掉终端窗口（或按 Ctrl+C）服务器就停了。

Mac 上第一次启动时系统会问「是否允许 Python 接受传入的网络连接」，要点**允许**，否则小电视和手机连不上。有人看电视时
Mac 不能睡眠：系统设置 → 电池（或节能）→ 接电源时防止自动睡眠。

### B. Docker（Linux 迷你主机、旧笔记本）——未验证

需要 Docker 和 Docker Compose（`docker compose version` 能看到版本号）。镜像还没有发布，第一次启动会在你的机器上构建，
要几分钟：

```bash
git clone https://github.com/rooma1989/ai-passport-tv.git
cd ai-passport-tv/packaging/docker
mkdir data                    # 先建好，容器才写得进去
docker compose up -d
docker compose logs tv        # 在这里找「设置码」
```

所有数据都在 `packaging/docker/data/` 里。容器以编号 1000 的用户运行，读不了写不了 `data` 时，日志会说明；在同一目录的
`.env` 文件里写 `PUID=…`、`PGID=…`（`id` 命令能看到你的编号）再 `docker compose up -d`。

容器里看不到你家的局域网地址，所以日志里写的是「这台电脑的地址」：换成运行 Docker 的那台机器的 IP（例如
`192.168.1.20`）。

### C. NAS（群晖、绿联、威联通）——未验证

1. 在 NAS 的文件管理里建一个文件夹，例如 `docker/xiaozhi-tv/data`。
2. 群晖 DSM 7.2 以上：Container Manager → 项目 → 新增，路径选 `docker/xiaozhi-tv`，内容贴上 `packaging/docker/compose.yaml`
   （镜像发布之前，NAS 上没法构建：等镜像发布，或在电脑上构建后 `docker save` 导入）。绿联 UGOS Pro 的 Docker 应用、
   威联通 Container Station 也是导入同一个 compose 文件。
3. PUID/PGID 填那个文件夹主人的编号；8080 被 NAS 别的应用占了，就把 compose 里的 `"8080:8080"` 改成 `"18080:8080"`，
   之后用 18080 打开网页。
4. 在 NAS 的容器日志里找「设置码」。

### Windows——未验证

用 Docker Desktop（需要 WSL 2，装完要重启一次），然后按上面 B 的步骤。第一次映射端口时 Windows 防火墙会弹窗，选
「专用网络」。电脑也不能睡眠。

## 第二步：第一次设置（设置码）

服务器启动时在日志（或终端）里打印一段话：

```
小智电视服务器已启动。
  用家里网络上的手机或电脑打开：http://192.168.1.20:8080/tv/setup
  设置码：K7P4Q-X2M9A   （只能用一次；用来建管理员）
  或者用手机扫这个码（设置码已经填好）：…
  小电视上的服务器地址填：192.168.1.20（不用写端口）
```

1. 用家里 Wi-Fi 上的手机打开那个地址（或扫终端里的二维码，设置码会自动填好）。
2. 输入设置码和你的名字，点「成为管理员」。第一个这样做的人就是管理员。
3. 按页面上的提示把手机遥控加到主屏幕。

设置码只能用一次；管理员建好之前，每次重启服务器都会换一个新的。设置页只在家里的网络上打开得了（隧道端口上没有）。
同一个网络 10 分钟里输错 5 次要等一会儿。

## 第三步：添加频道（你自己的）

服务器不带任何频道。管理员在电脑上打开 `http://<地址>:8080/tv/admin` → **频道表**：

- **一键添加央视、卫视**：在「导入播放列表」里选一个公开播放列表（iptv-org 中国或中文、vbskycn/iptv、myIPTV、Guovin iptv-api、APTV），
  点「读取」（GitHub 慢的时候点上游提供的加速按钮，例如 gh-proxy）。列表出来后点**央视**或**卫视**，再点「全选」、
  **加入频道表**，最后点下面的**保存**。以下是网上公开的第三方播放列表，内容由其维护者负责，本项目不提供也不保证任何
  直播源；请只添加你有权观看的内容。这些列表里的源过一阵就会失效一些，「试一下」（一次最多试 20 个勾选的台）能看出
  现在哪些能放。
- **从网址或文件导入**：粘贴一个 M3U 播放列表地址点「读取」，或「选文件」上传一个 `.m3u` 文件，之后一样。地址只在读取时
  取一次，不会保存。
- 地址或名字已经在表里的台、列表里重复的台标成「重复」，默认不勾，「全选」也不选；同一个地址不会加第二次。加的时候
  只加每个用户的小电视都放得下的，保存时还会再查一遍，并先备份原来的频道表。
- **加一个台**：名字加直播地址（`http(s)://…`）。
- 小电视最多收 128 个台，挑常看的就好。

也可以在手机遥控的「订阅」里添加 B 站 UP 主和剧集（每个人自己的）。YouTube 是可选的、默认关着，见下面的
[YouTube（可选）](#youtube可选)；本项目不提供访问办法。

一个台都没有时，已绑定的小电视显示「NO CHANNELS YET / ADD SOME / ON YOUR PHONE」，加了台以后它会自己重连。

## 节目单（可选）

默认关着，家庭服务器、电脑客户端和云端中转都一样。管理员在**频道表 → 节目单**里打开：勾选那里列出的公开节目单
（112114、fanmingming），或者填一个 XMLTV 文件的地址（`.xml`，压缩不压缩都行），最多 3 个，点**保存节目单设置**。
之后手机遥控的频道列表、电脑版的频道卡片和电脑上播放器的标题下面多一行，例如「正在播：新闻联播 19:00–19:30」。
以下是网上公开的第三方节目单，内容由其维护者负责，本项目不提供也不保证任何节目信息。

- 服务器每 8 小时取一次每个节目单，带上次的 ETag / Last-Modified 问（没变就不重新下载），原样存在数据库旁边的
  `epg/` 里（每份最多 50 MB）；没取到的 30 分钟后再试，旧文件照用。「现在更新」5 分钟内只能点一次。
- 在后台线程里边读边扔，只留频道表里有的台、前 1 小时到后 24 小时的节目。
- 对台：从播放列表导入的台带着 `tvg-id` / `tvg-name`（存在频道表旁边的 `channels.txt.meta.json`），再按台名：
  「CCTV-1」「CCTV1综合」「CCTV-1 HD」都是 CCTV1，「湖南卫视HD」是湖南卫视，没有自己节目单的 4K 台（浙江卫视4K）
  用不带 4K 的那个（CCTV4K 单独算）。页面上写着对上了几个台，并列出没对上的。
- 开销（2026-10-24 在 Mac 上用 fanmingming 的节目单实测：gzip 0.46 MB、XML 7 MB、124 个台、35590 条节目，
  频道表 93 个台）：读一遍 0.2–0.9 秒 CPU，Python 多用约 1 MB 内存；对上的 28 个台留在内存里约 0.5 MB，整个中转
  进程常驻 39 MB。112114 的节目单（gzip 0.2 MB、XML 3 MB）读一遍约 0.3 秒。Linux 上节目单线程的优先级调低。
  关着时不下载、没有线程、不占内存。

## 第四步：给小电视刷固件、配网、绑定

1. **刷固件**：小电视用 USB 线插在**服务器那台电脑**上，在那台电脑上用 Chrome 或 Edge 打开
   **`http://localhost:8080/flash/`**（端口改过就用你的端口）。浏览器只在 `https://` 或 `localhost` 的页面上允许网页
   串口，所以**用局域网 IP（`http://192.168.x.x:8080/flash/`）打开是刷不了的**，页面会这样提示。页面自己认芯片：星智 Cube
   第一次刷要先整片擦除（会去掉小智 AI 原来的固件，要你打勾同意），以后再刷只更新、不擦除；AI Passport **绝不擦除**。
   - 服务器的刷机页要有固件文件：不用 Docker 时运行 `./run.sh --fetch-firmware`（下载最新发布的
     `xiaozhi-tv-flasher.zip`，校验后放进数据文件夹的 `firmware/`），或者自己下载这个 zip 解压进 `firmware/`，然后重启服务器；
     Docker 镜像构建时已经带了最新发布的固件，数据文件夹的 `firmware/` 里有的话优先用它。
   - 服务器在 NAS 上、或小电视插在另一台电脑上：把 `xiaozhi-tv-flasher.zip` 解压后放到任何 **https** 网站的 `/flash/` 下
     （项目网站上的刷机页由阶段 S4 发布，地址公布后写在这里），在插着小电视的电脑上打开。
   - 总后台「设备」页会标出可以更新固件的小电视，并链到 `/flash/`。
2. **配网（声波）**：小电视开机进入配网页后，用手机打开 `http://<地址>:8080/tv/wifi`（设置完成页上也有链接），填 Wi-Fi 名称和
   密码，服务器地址会自动填成上面横幅里的地址（不用写端口），点「发送」，把手机靠近小电视。
   **热点配网**（备用）：手机连上小电视的热点，打开 `192.168.4.1`，填 Wi-Fi 和服务器地址。
3. **绑定**：小电视连上后显示「BIND THIS TV」和 6 位数字的绑定码（云端服务是 20 位，自建服务器是 6 位数字）。用已登录的
   手机：手机相机扫小电视状态页上的二维码，或在遥控「我的 → 绑定新设备」里扫码或输入那串码。绑好后小电视就播你的频道。
   输错有限制：每个手机地址 10 分钟最多错 5 次、全部加起来最多 30 次，之后暂停绑定（最多 10 分钟）；错满 30 次时所有
   未绑定的小电视还会换新码，几秒内屏幕上就是新码。旧版本留下的 20 位绑定码，小电视下次连上时会换成 6 位数字。

服务器的地址要一直不变：在路由器里给它固定 IP 最稳。也可以试 `电脑名.local` 这样的名字，但还没在小电视上验证过。

## YouTube（可选）

YouTube 默认关着；B 站和直播频道不用它也能看。打开它是给已经有办法从这台电脑访问 YouTube 的家庭用的：**本项目不提供
代理，也不介绍怎么获得代理。**

1. 在电脑版（用管理员登录）打开 **设置 → YouTube**，选 **本机**；或者在 `config.toml` 里写 `[youtube] mode = "local"`
   和 `proxy = "…"`，再重启服务器。
2. 代理：填你的代理软件给这台电脑的地址，例如 `http://127.0.0.1:端口` 或 `socks5://127.0.0.1:端口`；或者点
   **自动检测**，它读系统代理（macOS 的网络代理设置、Windows 的代理设置、Linux 的 `https_proxy` / `all_proxy`
   环境变量）并把找到的填进去。代理软件开着 TUN（增强）模式、或者本来就能直连 YouTube 时，留空。
3. 点 **保存**。第一次会下载两个 YouTube 组件 yt-dlp 和 deno（约 80 MB，经这个代理；也可以填一个下载镜像前缀：用来替换下载地址里的 `https://github.com`，
   要整个网址的 GitHub 加速站写成 `https://加速站/https://github.com`），
   每个文件都按程序里写死的 SHA-256 核对。进度就显示在这一节里。
4. 点 **测试**：解析一个公开的测试视频，用大白话告诉你结果（「成功：12 秒」「连不上 YouTube：检查代理」「需要登录：
   导入 cookies」）。
5. **Cookies**：YouTube 常常要求代理、机房的地址「登录证明不是机器人」。这时导入一个 `cookies.txt`（Netscape 格式）：
   用一个**小号**，在浏览器的无痕（隐私）窗口里登录小号、打开 YouTube，用导出 cookies.txt 的扩展只导出 youtube.com，
   然后直接关掉无痕窗口（不要退出登录，退出会让 cookies 作废）。服务器只留 youtube.com 和 google.com 的条目，存在
   `<数据目录>/youtube/cookies.txt`（只有你能读），页面上只显示条数。这个文件就是小号的登录凭据：不要发给别人。
6. YouTube 改版很勤。视频放不出来时，点 **检查更新**、**更新 yt-dlp**（新版本按它发布页自己的 `SHA2-256SUMS` 核对）。

改了不用重启服务器：保存后只重启变了的部分（只改代理就只重启 YouTube 的那个小服务）。之后 YouTube 视频、频道（UP 主）
和播放列表（剧集）和云端一样用。「自己的节点」给自己架了 YouTube 节点的人用（`secrets/youtube-node.json`）。

Docker 里的 `127.0.0.1` 是容器自己：代理要写主机的局域网地址（并让代理软件允许局域网连接），「自动检测」也只看得到容器
里的环境变量。组件放在 `/data/youtube/bin/`（Linux 的 amd64 或 arm64；32 位 ARM 不支持）。

## 家人和客人

和云端一样：「我的 → 让另一部手机登录」（同一个账号，最简单）、邀请（各自的账号）、客人扫小电视的二维码当访客。
推荐一家人共用一个账号，客人用访客码。

## 备份和更新

- 整个数据文件夹就是你的全部东西（不用备份里面的 `run/`）。服务器每天凌晨 3 点后备份一次数据库到 `backups/`，留 14 天
  （`config.toml` 的 `backup_keep_days`）。**`secrets/` 里是密钥**（`youtube/cookies.txt` 是 YouTube 的登录），备份文件要像密码一样保管，不要发给别人。
  `youtube/bin/` 不用备份（会重新下载）。
- 恢复：停掉服务器，把数据文件夹换成备份，再启动。
- 更新：不用 Docker 时 `git pull` 后重启；Docker：`git pull` 后 `docker compose up -d --build`（镜像发布后改成
  `docker compose pull && docker compose up -d`）。

## 设置文件

第一次启动时在数据文件夹里写出带注释的 `config.toml`，改完重启生效。常用的几项：

| 项 | 默认 | 作用 |
| --- | --- | --- |
| `[server] lan_port` | 8080 | 网页端口 |
| `[server] device_address` | 空 | 小电视连的地址；空 = 第一次设置时记下浏览器用的地址 |
| `[server] public_port` | 0 | 给隧道（Cloudflare Tunnel、Tailscale serve）用的端口，例如 8081；隧道端口上没有总后台、设置页和密钥登录 |
| `[devices] allow_internet` | false | 允许公网地址的设备连进来（只在端口转发时需要） |
| `[accounts] signup_via_device` | "lan" | 扫未绑定小电视的码自己注册：只在家里网络 / 隧道也行 / 不允许 |
| `[youtube] mode`、`proxy` | "off"、空 | YouTube：关闭 / `local`（这台机器经 `proxy` 取）/ `node`（自己的节点）；电脑版「设置 → YouTube」会改这两行并且不用重启就生效 |

## 常见问题

- **打不开网页**：手机和服务器在同一个 Wi-Fi 吗？Mac 的防火墙弹窗点了允许吗？端口被占用时改 `lan_port`。
- **小电视显示「服务器没有回应」**：服务器地址填对了吗（局域网 IP，不带端口）？同一型号的另一台正在看吗（测试版一次一台）？
- **登录不住**：用 `http://<局域网 IP>:8080` 打开；`localhost`、IP、`.local` 名字、隧道网址各算各的登录。
- **页面里的「扫一扫」打不开相机**：明文 HTTP 上浏览器不给网页用相机，用手机自带的相机扫码，或输入码。
- **复制按钮没反应**：同样是明文 HTTP 的限制，手动选中复制。
