## 1. 为什么改，改什么

电脑版（`server/relay/assets/console.html`）和手机页（`assets/remote.html`）当初是**小电视的遥控器**：
打开先是一块屏幕读数和一格格频道，内容藏在表单里（粘贴链接、UP 主表格、放过的表格）。现在产品是家庭媒体中心：
好几台小电视，电脑自己也能播（「在电脑上看」，有没有小电视都行），好几种内容来源，好几个家人，接下来还有本地片库。
主人希望它像 Infuse、Jellyfin、Apple TV app 或 Plex。

设计保留今天页面能做的一切，把它们挪到「内容优先」的结构下，并加三个贯穿各处的东西：

1. **「播放到」**：每个播放按钮共用一个目标选择器（每台小电视，加「这台电脑」），记住上次的选择，显示哪台在线。
2. **遥控面板**：每台设备的控制（音量、亮度、只听、宠物、定时关、换台、暂停、快进快退）放在一个随处可打开的
   抽屉里，不再当首页。
3. **统一的媒体条目**：直播节目、UP 主视频、剧集分集、投屏链接、片库文件用同一种数据形状，所以货架、搜索、
   放过的、继续观看都用同一种画法。

### 目标

- 内容优先：第一屏回答「现在能看什么」（继续观看、正在直播、UP 主更新、剧集追更、我的片库）。
- 每个能播的东西有一个主操作：「播放」到记住的目标；还有一个次操作「播放到…」打开选择器。
- 电脑和手机的信息架构一样，布局不同。
- 电脑上能用键盘和遥控器式（方向键）导航；手机上点击区域够大。
- 安静、像电视盒子系统界面的样子（第 10 节）：默认深色，大圆角封面，焦点让卡片浮起来，半透明毛玻璃材质。
  界面里画小电视自己屏幕的地方，保留那块屏幕的琥珀色数字。

### 不做的

- 不改设备固件、协议和小电视自己的屏幕菜单。
- 除了计划中的本地片库和可选的 Jellyfin/Emby/Plex 连接，不加新的内容来源。
- 第一版不发浅色主题：它已经设计好、原型里能切换，在 M9 发（Q10）。
- 不做推荐算法：首页只由家里自己的订阅、播放记录和 EPG 拼出来。

## 2. 信息架构

桌面：**顶部标签栏**，六个标签放在居中的半透明胶囊里（首页、直播、剧集、UP 主、片库、搜索），左边是字标，右边是
「播放到」小标签、**设备与遥控** 和 **设置** 两个图标，以及当前用户。标签栏在大图上是透明的，页面一滚动就变成毛玻璃。
节目单不再是顶层入口：它是「直播」的第二个分段（「节目指南 | 小电视频道表」）。正在播放栏浮在底部。手机：底部五个标签。

| 入口 | 内容 | 取代今天的 |
| --- | --- | --- |
| **首页** | 大图（最多三个）、货架：继续观看、直播·正在播、UP 主更新、剧集追更、我的片库 | 作为首页的「遥控」页 |
| **直播** | 上面是选中的节目（台、标题、进度、接下来、播放 / 在电脑上看），分组标签，带时间尺和「现在」红线的节目单网格 | 「遥控」页上的频道格子 |
| **节目单**（「直播」的第二个分段，界面上叫「小电视频道表」） | 每台小电视按上/下换台的那张频道表：按台分开，分组、顺序、显示/隐藏、容量（台数和字节），直播源和预设，EPG 状态 | 「调整分组」链接、总后台频道表的预设 |
| **剧集与番剧** | 海报墙，可筛选（追更中、番剧、电视剧、纪录片、动画、看完了）；添加剧集 | 「订阅」页的剧集表 |
| **UP 主** | 头像条（带新视频数）、最新视频网格、订阅、从 B 站导入 | 「订阅」页的 UP 主表 |
| **片库** | 本地文件夹和媒体服务器：电影、剧集、动画、家庭视频；来源条 | 新的 |
| **搜索** | 一个搜索框覆盖直播（台和 EPG）、剧集、片库、UP 主、视频（B 站、YouTube）；范围标签；在结果上直接添加 / 订阅 | 「订阅」页的 B 站搜索；粘贴链接投屏也在这里 |
| **设备与遥控** | 设备卡片（屏幕示意、在线状态、正在播、遥控、设为默认播放位置、在电脑上看）、这台电脑、绑定新的小电视、让手机登录、家人和访客 | 「设备」页；「遥控」的控件挪进遥控面板 |
| **设置** | 播放（「播放到」是否记住）、内容来源（直播源和 EPG、B 站账号、YouTube、片库文件夹、媒体服务器）、家里（设备、家人、登录的地方）、关于 | 「设置」和「邀请」 |

手机的标签是 **首页、直播、搜索、遥控、我的**。「遥控」是整页的遥控面板（手机的老本行一点就到）。「我的」里列着
剧集与番剧、UP 主、片库、节目单、设备、设置和放过的。首页顶部还有快捷标签直达剧集、UP 主、片库和节目单。

「投屏」不再是单独一页：把 B 站或 YouTube 链接粘进任何搜索框，第一个结果就是「播放这个链接」，照样走「播放到」。
「放过的」（最多 50 个）在手机的「我的」里，在桌面的设置里，条目也用同一种媒体条目形状。

**详情页**（从海报和搜索进入）：铺满的背景图加标题图（元数据里有标题 logo 图就用，没有就把标题排成大字）、信息行
（年份、类型、来源、更新时间）、简介、带进度线的「上次在 <设备> 看到 <位置>」、操作（继续第 N 集 + 位置、播放到…、
从第 1 集、追更中）、选集做成一排 16:9 卡片（看过 / 看到这里 / 还没更新；还没更新的卡片不能点，焦点跳过它）、同类货架。片库的电影显示文件信息（分辨率、编码、字幕、大小、所在文件夹），并说明播放到小电视时由电脑转码。

## 3. 正在播放栏

一直在底部（手机上在标签栏上面）。它跟随**用户最后一次开始或操作的那一路播放**：封面、标题、「<设备> · <节目或进度>」、
进度线、上一个 / 播放暂停 / 下一个、小电视的遥控按钮。桌面上它是浮在内容上的毛玻璃胶囊（最宽 960 px）；「播放到」
小标签留在顶栏，不在这里重复。点封面打开正在播的东西（直播是
节目单，剧集或片库是详情页）。目标是这台电脑时，播放栏控制页面里的播放窗口，保留今天的「跟随小电视换台」选项。

空闲时：「没有在播」加「播放到」小标签。

## 4. 播放到

### 4.1 行为

- **目标**：用户能遥控的每台小电视（主人、家人，或访客唯一能控制的那台），电脑版上再加 **这台电脑**。手机上第一版
  不提供「这台手机」（手机上听已有只听页面；手机上完整播放见 Q8）。
- 每一行显示：图标（小电视或电脑）、名字、在线圆点、型号和分辨率、正在播什么（或「离线 · 3 小时前在线」），记住的
  那台带 **上次用的** 标记。
- **主播放按钮** 立刻播到记住的目标，并用小字说明播到哪（「到客厅」）。旁边的箭头打开这个条目的选择器，选一行就播在那里。
- **顶栏小标签** 打开同一个选择器但不带条目：只改默认目标，正在播的不会被打断。
- **记住这次的选择** 开关（默认开）。关掉后每次点播放都先问。
- **目标离线**：那一行变暗、不能选。如果点播放时记住的目标离线了，选择器会弹出并给一句提示，而不是直接失败。
- **没有绑定小电视**：只列出这台电脑，附「绑定一台」链接；所有播放都在电脑上。
- 选择器在桌面上是右侧抽屉，在手机上是底部弹出层；它是一个单选组，Esc 或点遮罩关闭，焦点回到打开它的按钮。

### 4.2 选择器遵守的内容规则

| 条目 | 播到小电视 | 播到这台电脑 |
| --- | --- | --- |
| 直播台 | 小电视换到这个台（今天的 `/api/switch`） | 直接看这个台（今天的 `watch_direct`） |
| UP 主视频 / 剧集分集 | 在 UP 主台或剧集台上播这一个（今天的 `/api/subs/play`、选集） | 直接看；进度另记（Q4） |
| 投屏链接 | 那台小电视的投屏位 | 投到电脑 |
| 片库条目 | 电脑把文件转成小电视的分辨率（新） | 电脑在页面里播文件（新） |
| YouTube 条目，YouTube 没开 | 那一行不能选，「去设置里开启 YouTube」 | 同左 |
| B 站大会员分集，没登录 | 那一行不能选，带登录链接 | 同左 |

### 4.3 「记住」存在哪

按浏览器存在 `localStorage` 里，按用户分开：书房的电脑和卧室的手机本来就对着不同的屏幕。没存过时用服务器的「自动」
目标（今天 `/api/state` 里的 `auto`）。见 Q3。

## 5. 遥控面板

一个组件，从设备卡片的遥控按钮、正在播放栏或手机的「遥控」标签打开。从上到下：

1. **设备标签**：在小电视之间切换（离线的变暗；选中离线的显示「离线，……在线过，看看电源和 Wi-Fi」）。
2. **屏幕读数**，沿用今天的样子：琥珀色大号台号、分组、台名或 UP 主名、EPG 给的节目和进度线、「接下来 ……」；
   点播内容显示视频标题和进度。
3. **按键**：上一台、暂停/继续、下一台；退 30 秒、下一个、进 30 秒（直播时快进快退和下一个不可用）。
4. **调节**：音量滑块（每格 10）、亮度五档、只听开关（「只放声音，屏幕只显示宠物」）、定时关（关、15、30、60、
   90 分钟，显示「还剩 N 分钟」；今天只有语音能定时，所以要加 `POST /api/sleep`）。
5. **宠物**：六只可选，当前的那只带框。
6. **在电脑上看这个**，以及去这台小电视频道表的链接。

桌面：浮在当前页右侧的 440 px 面板。手机：「遥控」标签就是整页面板；从别处打开时是底部弹出层。改动马上生效并
弹一句提示，和今天一样。每个控件的点击区域桌面至少 44 px，手机 52–58 px。

## 7. 空状态和出错状态

| 情况 | 用户看到的 |
| --- | --- |
| 没有绑定小电视 | 首页横幅「没有小电视也能用小鼠电视：点任何节目都在这台电脑上播放；以后输入小电视屏幕上的绑定码就行」；「播放到」里只有这台电脑；设备页有一张带「绑定」的空卡片；节目单和手机的「遥控」标签说明需要小电视 |
| 小电视都离线 | 选择器里那几行变暗；「遥控」标签显示「小电视都离线了」，带去设备页的链接 |
| 没订阅、片库为空 | 首页保留大图（只有直播）和「直播·正在播」；其他货架换成三张引导卡（订阅一个 UP 主、加一部剧、添加片库文件夹）；剧集、UP 主、片库页各有带添加按钮的空状态 |
| 连不上 B 站 | 首页、剧集、UP 主、搜索显示警告横幅（「连不上 B 站：UP 主和剧集暂时不更新；直播、YouTube 和片库照常」）；没缓存的封面换成中性的「封面暂时取不到」占位图，标题照样显示在下面；搜索只给本地、直播和 YouTube 的结果；设置里 B 站账号那一行写明原因 |
| YouTube 没开 | YouTube 条目不能播，带去设置的链接，不藏起来 |
| 某个台没有 EPG | 只显示台名和台标；没有「正在播 / 接下来」，节目单网格里是一整条「没有节目信息」 |
| M3U 没有台标 | 生成的标记：台的短名放在由台名算出的颜色上 |
| 片库文件夹不在（NAS 没挂上） | 来源标签变红「连不上」；条目还在但变灰，写「文件夹离线」 |
| 节目单里点了已播完 / 还没开始的节目 | 「已经播完 · 暂不支持回看」/「21:00 开始 · 提醒我（以后）」；两种都提供「看这个台现在播的」 |

## 8. 每一行需要的数据

所有货架都画同一种 **媒体条目**：`id`、`kind`（`live`、`episode`、`video`、`cast`、`library`）、`title`、
`subtitle`、`art`（地址和比例 `poster` 或 `wide`）、可选的 `progress`（`position`、`duration`、`device`、
`updated_at`）、可选的 `live`（`channel`、`start`、`end`、`next_title`、`next_start`）、`source`（`m3u`、
`bilibili`、`youtube`、`library`、`jellyfin`……）、`detail`（详情页路由或没有）和 `playable`（每个目标能不能播，
不能时带原因）。

| 货架 / 页面 | 字段 | 来源 | 今天有吗？ |
| --- | --- | --- | --- |
| 继续观看 | 条目、进度、时长、设备、时间 | `state.py` 里的剧集分集和 UP 主看过记录；进度位置是**新的**（视频、片库、电脑上看） | 部分有 |
| 直播·正在播 | 台号、台标、台名、分组、当前节目标题/开始/结束、下一个 | 频道表 + EPG（`desktop-epg`）；台标来自 M3U 的 `tvg-logo` | EPG 待合入 |
| UP 主更新 | 视频标题、时长、发布时间、UP 主头像和名字、「新」标记 | UP 主视频列表（最新 20 个）、看过记录 | 有，头像是新的 |

- YouTube 缩略图：给同一个代理的白名单加 `i.ytimg.com`，经 YouTube 已经在用的代理去取。

## 9. 无障碍

- **电脑上的键盘和遥控器式导航。** 方向键把焦点移到那个方向最近的可聚焦元素，先在同一块区域里找（内容区、顶栏、
  正在播放栏、面板；手机上还有底部标签栏），找不到才跨区域。在一排货架里左右移动只在这一排里走，排尾不会跳到别的排。
  回车执行。Esc 就是遥控器上的「返回」：关面板 → 退出输入框 → 详情页后退 → 否则把焦点移到标签栏 → 在标签栏上再按回首页。
  在详情页按退格也返回；`/` 打开搜索。滑块保留左右键，上下键离开滑块。货架平滑滚动，让聚焦的卡片完整露出来，页面也滚到
  这一排不被顶栏和正在播放栏挡住。点播放后页面重画，焦点还在原来那个条目上。客厅电脑配遥控器或键盘时需要的就是这些。
  原型全部实现了。
- **焦点**始终看得见（第 10 节）：卡片浮起、放大、带一点反光；按钮、标签和分段变成焦点色；其他东西有 2 px 描边。
  面板里 Tab 不会跑出去，关闭后焦点回到打开它的地方。
- **对比度**：文字颜色变量在两种主题的底色上做小字都至少 4.5:1（`--label-3` 约 5:1）；`--label-4` 只用于装饰。
  图上的文字下面有深色渐变，永远是白字。
- **点击区域**：桌面控件至少 44 px（按钮 46 px，标签 40 px 高、胶囊 50 px）；手机按钮 50 px，遥控按键 60 px，
  列表行 60 px，底部标签 54 px。
- **语义**：导航地标，当前项 `aria-current`，标签和分段按钮的按下状态，开关用 `role="switch"`，选择器是
  `radiogroup`，面板是带 `aria-modal` 的 `role="dialog"`，提示放在 `aria-live` 区域里，每个只有图的按钮都有名字
  （「播放 <标题>」「遥控 <设备>」）。
- **动效**：不自动播放视频，大图不自动轮播，用户点播放之前什么都不出声；`prefers-reduced-motion` 时关掉过渡、卡片倾斜和反光。

## 10. 视觉语言

2026-10-24 修订。第一版的暖红 + 宋体换成更像电视盒子系统界面的样子；主人给的参照是 Apple TV app 和 tvOS。只借它的
气质，不抄任何东西：没有 Apple 标志、没有「TV+」字样、不用 Apple 的图标和素材；所有图标都是为这个项目画的简单内联 SVG。

**颜色变量。** 默认深色；浅色主题重新定义同一组名字。图片上的区域（首页大图、详情背景、浮在它们上面时的顶栏）用
`.dk` 固定成深色，所以两种主题里图上的字都是白的。

| 变量 | 深色 | 浅色 | 用途 |
| --- | --- | --- | --- |
| `--bg`、`--bg-2`、`--bg-3` | #0b0b0d、#1a1a1d、#26262b | #f2f2f6、#ffffff、#e4e4ea | 页面；分组列表和面板；封面占位 |
| `--fill`、`--fill-2`、`--fill-3` | 白 8 %、14 %、24 % | 黑 5 %、8 %、15 % | 按钮、标签、节目块、滑轨 |
| `--label`、`--label-2`、`--label-3` | #f5f5f7、68 %、55 % | #111113、80 %、66 % | 文字层级；`--label-4`（约 30 %）只用于装饰 |
| `--sep` | 白 10 % | 黑 10 % | 细分隔线 |
| `--mat`、`--mat-thick` | rgba(40,40,46,.52)、rgba(26,26,30,.80) | 白 62 %、rgba(248,248,251,.84) | 材质，总是配模糊 |
| `--focus-bg`、`--focus-fg` | #f5f5f7、#0b0b0d | #111113、#ffffff | 获得焦点的控件 |
| `--brand` | #ff6b3d，渐变到 #ffb05a | 同左 | 手机当前标签、节目单「现在」线、「新」标记、开关、主按钮的焦点外圈 |
| `--live`、`--ok` | #ff4b3e、#34c76a | 同左 | 「直播」标记；在线圆点 |

小电视自己的屏幕（设备卡片、遥控面板的屏幕读数）在两种主题里都保留固件的琥珀色等宽数字，因为画的就是那块屏幕。

**材质。** `backdrop-filter: saturate(180%) blur(28px)`，底色用 `--mat`（标签胶囊、「播放到」小标签、图上的标记）或
`--mat-thick`（滚动后的顶栏、正在播放栏、面板、提示、手机标签栏）。浏览器不支持模糊时，厚材质的颜色也够不透明，字照样看得清。

**形状。** 圆角 6 px（标记）、10 px（小按钮、节目块）、12 px（按钮、海报）、14 px（横图卡）、16–20 px（列表、面板、
搜索框、节目单）、22–26 px（正在播放栏、面板），标签和分段是全圆。海报 2:3，其余 16:9。阴影：卡片 `0 8px 22px`
38 %（浅色 12 %），焦点卡片 `0 30px 56px` 62 %（浅色 26 %）。浅色主题里大图不往白色页面里渐隐：下沿加深收住，第一排
货架从它下面开始。

**动效。** 焦点和悬停 220 ms `cubic-bezier(.2,.8,.2,1)`；颜色变化 140 ms；淡入淡出 260 ms；面板 380 ms
`cubic-bezier(.32,.72,0,1)`，桌面从右边、手机从底下出来；卡片刚获得焦点时的反光扫一次，900 ms。
`prefers-reduced-motion` 时全部关掉。

**焦点。** 获得焦点或鼠标悬停的卡片上浮 6 px、放大到 1.07、阴影加深、带一片柔和的高光；用鼠标时还会朝指针方向倾斜
约 4 度，高光跟着指针走；键盘焦点改成扫一次反光。卡片下面的文字往下让 5 px。按钮、标签、分段变成焦点色（深色主题里
是白底黑字），放大 1.05–1.07；节目块变成焦点色，只放大 1.04；列表行加底色和 2 px 内描边。手机上卡片只放大到 1.04。
键盘焦点在内容区时，鼠标指到另一张卡片会把焦点挪过去，不会同时有两张卡片浮起来。

**字体。** 只用系统字体，不加载网页字体：`-apple-system, "SF Pro Display", "PingFang SC", "Helvetica Neue", sans-serif`，
数字和时间用等宽数字。字号：标题图 66 px / 800（长标题 52 px，手机 40 px）；大标题 40 px / 700（手机 34 px）；
直播和详情的标题 32 px / 700；货架和面板标题 22 px / 700（手机 20 px）；正文 15 px；次要文字 13–14 px；说明 12 px；
手机标签文字 10.5 px。标题图：元数据给了 logo 图就用图；没有就把标题排成大字，带一点从封面色调来的渐变。

**节奏。** 内容边距桌面 56 px、手机 16 px；卡片间距 24 px（手机 14 px）；货架之间 30 px；用留白而不是分隔线和边框分区。

## 11. 要加的接口

现有接口都保留；新接口把它们汇总起来，免得画一个首页要发十个请求。

| 接口 | 用途 |
| --- | --- |
| `GET /api/home` | 首页一次拿全：`hero[]`、`continue[]`、`live_now[]`、`creator_updates[]`、`series_updates[]`、`library_recent[]`，每项都是媒体条目；按调用者；缓存几秒；访客只有 `live_now` |
| `GET /api/guide?from=&to=&group=` | 一个时间窗口里的台和节目（来自 EPG 那边）；带台号、分组、台标地址 |
| `GET /api/targets` | 「播放到」的各行：每台能遥控的小电视加这台电脑，带在线、上次在线、型号、分辨率、正在播、能力（能否快进、只听）；也可以并进 `/api/state.devices` 再加一行 `pc` |
| `POST /api/play` | `{item, target}` —— 一个入口，分发到今天的换台、subs/play、history/play、投屏和在电脑上看；返回开始的播放，或原因（`offline`、`needs_login`、`youtube_off`） |
| `GET/PUT /api/progress/{item}` | 每个用户每个条目的续播位置，带上报它的设备；由电视服务和电脑上的播放器写 |
| `GET /api/search?q=&scope=` | 分组结果：台和 EPG、剧集、UP 主、片库，加上 B 站（现有搜索，限流照旧）和 YouTube；粘贴的链接变成「播放这个链接」 |
| `GET /api/art/logo/{channel}`、`/api/library/art/{id}` | 缓存的台标和海报（第 8 节）；缩略图代理的白名单加 YouTube |
| `GET /api/library`、`GET /api/library/{id}`、`POST /api/library/folders`、`GET /api/library/scan` | 片库索引、条目详情、文件夹管理、扫描状态 |
| `POST /api/connectors/{jellyfin,emby,plex}` | 可选的媒体服务器连接（地址，令牌只存在这台电脑上），映射成同一种条目形状 |
| `POST /api/sleep` | `{device, minutes}`（0 取消）：遥控面板的定时关，复用语音命令的定时暂停；剩余时间在 `/api/state` 里报告 |
| `GET /api/events`（SSE，可选） | 推送正在播、在线状态和进度的变化，代替轮询 `/api/state` |

## 13. 请你决定的问题

主人在 2026-10-24 接受了 Q1–Q11 的全部建议。同一天的视觉修订改了其中两条（Q2、Q10）；Q12、Q13 是新的，还没定。

**Q1. 一个响应式页面，还是两个页面？** 今天电脑版和手机页是两个文件，样式重复。*建议：* 先做共用的外壳和组件资源
（M0），两个页面都用它；手机布局验证过后在 M6 合成一个响应式页面。访客保留精简视图。

**Q2. 「节目单」指什么。** 原型把它理解成**小电视的频道表**（按上/下换台时轮的那些台，每台小电视一张，带分组、
顺序、预设和容量），因为「直播」里已经有节目时间表。*已接受，后来修订：* 换成顶部标签栏以后，桌面上它是「直播」的第二个分段
（「节目指南 | 小电视频道表」），手机上仍在「我的」里。

**Q3. 「播放到」怎么记住。** 按浏览器、按账号，还是每次都问？*建议：* 按浏览器，默认记住，服务器的自动目标兜底；
选择器里一个开关就能变成「每次都问」。

**Q4. 在电脑上看的进度。** 今天在电脑上看故意不标看过、也不推进小电视的剧集位置。继续观看需要位置。*建议：* 电脑上的
位置单独记，带设备名显示在继续观看里；除非用户选「从这里在 <小电视> 上接着播」，否则绝不因为电脑上看过就推进小电视
那个台的进度。

**Q5. 首页大图。** *建议：* 最多三个，自动挑（追的剧更新了一集、EPG 标出的直播或最常看的台、片库最新加入的）；不自动
播放，不自动轮播。

**Q6. 片库第一版的范围。** *建议：* 操作系统看得到的任何文件夹（用户自己挂上的 NAS 共享也算）；元数据只用本地
`.nfo`、海报文件和文件名解析；第一版不联网刮削（TMDB 的密钥、隐私、国内能不能连上），以后做成可选。

**Q7. 媒体服务器。** *建议：* 先 Jellyfin 和 Emby（开放、同一套 API），之后 Plex；只读浏览和播放，不做同步。

**Q8. 「这台手机」作为目标。** 手机上看完整视频会给电脑加新负担（转码，在外面时还走云端通道的带宽）。*建议：* 第一版
不做；保留现有的手机上听；M6 之后再看。

**Q9. 谁能看到片库？** *建议：* 家人看到整个片库；访客永远看不到；以后加按文件夹「只有我」。

**Q10. 浅色主题。** *已接受，后来修订：* 深色仍是默认、先发；浅色主题已经设计好（第 10 节，原型面板里能切换），在 M9 发。

**Q11. 台标。** *建议：* 在加载频道表时缓存、本地提供（第 8 节）；绝不按需代理任意台标地址。

- **电脑上的进度（Q4）**：在这台电脑上看到的位置按用户存在 `<数据目录>/pc-progress.json`（`home.PcProgress`），
  在「继续观看」里显示为「这台电脑」，重启后接着看也从这里起，从不标看过、不挪小电视的进度。主人状态里已经存着的
  小电视进度也在这一排，显示为「小电视」。
- **台标（Q11）**：`GET /api/art/logo/<台>`（`server/relay/logos.py`）只收台 id，地址来自 `channels.txt.meta.json`。
  第一次有人要时取一次（不是读频道表时），只走 http(s)、只连公网地址，最多 256 KB，按文件头只收 PNG/JPEG/GIF/WebP
  （不收 SVG），存在 `<数据目录>/logos/`；取不到的 6 小时后再试；没有台标的台回答一个可缓存的 404，页面画徽标。
- **电脑上的播放器（M2 之后）**：播放窗口用自己的控制条（播放 / 暂停、按视频时间线的位置和总长、能拖的进度条和已缓冲的
  范围、后退 / 前进 10 秒、音量和静音、全屏、下一集、选集面板；有焦点、放大或全屏时可以用空格、← →、F、M、Esc）。
  位置 = 回答里的 `start` + 媒体时间 − 第一段的媒体时间（列表里的 `#EXT-X-RTV-ORIGIN`，`watch.Window.origin`）；
  总长 = 回答里的 `duration`（B 站的视频信息和分 P、YouTube、订阅列表）。缓冲里有的地方直接跳；没有的，页面带 `start`
  再要一次 `POST /api/watch`，换一路新的（ffmpeg 带 `-ss`，新编号、新令牌）和新的 MediaSource；跟随小电视时跳转给这个页面
  另起一路，不动小电视。选集：多 P 视频（`pages`）、合集（`ugc_season`）、番剧的一季、YouTube 播放列表（`Bilibili.parts`、
  `client.series`），以及剧集台和 UP 主台；投到电脑的一项按 `{video: {site, id}, part}` 指，信息缓存 30 分钟。电脑上的进度
  每 10 秒和关闭时报一次（`POST /api/watch/progress`、`/api/watch/stop`），按用户、节目和第几集存，连同电脑上看完了的集
  （`done`），下次接着看（有「从头播放」）；看完的一集接着放下一集——放完时（倒数 5 秒）和下次再打开时都是。
- **点播（VOD）**：浏览器能直接放的 B 站视频——html5 playurl 的单段 H.264 MP4（最高 720p）——不再经 ffmpeg：
  页面请求里带 `vod: true`（和 `quality`），`web.py` 的 `_vod_source` 回答 `mode: "vod"`、`vod/<编号>/<令牌>/media`、
  起点和时长；放哪一项、哪一集、从哪里起，和 HLS 那条路用同一套代码选。`server/relay/vod.py` 转发文件，Range 原样带过去
  （206 / Content-Range / Content-Length / Accept-Ranges，补上 Referer 和 User-Agent），每次 64 KB 边收边发不落盘，浏览器
  掐掉请求时关上游，403 / 404 / 410 时（以及取到 90 分钟后）重新取一次地址，每一路同时至多 4 个请求（多了掐掉最早的），
  名额和 `watch.py` 一起算，180 秒没有请求、没有进度报告就收掉（暂停的页面每分钟报一次）。`console.js` 的 `VodPlayer`
  是同一套控制条后面的 `<video>`：位置就是 `currentTime`，跳转交给浏览器，已缓冲的范围取自播放器，倍速 0.75–2 倍
  （记住；`<` `>`），画中画（`P`），起点用 `#t=` 和 `loadedmetadata`。第一帧之前出错就换成 HLS（请求里不带 `vod`）；
  放到一半出错从同一个位置重新打开一次。登录了 B 站的账号有 720P（点播，默认）/ 1080P（HLS）的菜单，每个浏览器记住。
  直播、分段的、FLV、HEVC 和小电视照旧是 HLS / 中转的播放流。
- **YouTube 点播（DASH over MSE，2026-10-26，分支 `desktop-ytvod`）**：以前 YouTube 要等 yt-dlp（带 JS 验证）和实时速度的
  ffmpeg MPEG-TS → HLS 出了第一段才有画面，每拖一次进度条整条链重来。现在只在 YouTube 本机模式下（googlevideo 的地址绑着
  解析时的出口 IP；用 cstone 节点时绑的是 cstone 的），`server/relay/ytvod.py` 照 YouTube 自己网页的放法来。节点多了
  `GET /yt/formats?id=[&prefetch=1][&fresh=1]`：yt-dlp 解析到的全部直连格式（编码、大小、地址、http 头，给了时带
  `init_range` / `index_range`），和 `/yt/stream` 共用缓存（现在只留用得着的几项，至多 48 个视频）；旧节点回答 404 Not Found，
  中转照旧 HLS。中转按视频把回答留在内存里（LRU 64 个），留到 googlevideo 的 `expire` 前 30 分钟（至多 5 小时），同一个视频
  同时只解析一次。`choose` 选页面要的清晰度以内最好的只有画面的 H.264（360p / 480p / 720p / 1080p，默认 720p，`rootv.ytQuality`；
  没有不超过的就取最低的），加原声、没压动态范围的 AAC；只有 VP9 / AV1 的、页面没有 MediaSource 的给 360p 合体文件（格式 18），
  经同一个 Range 转发、`VodPlayer` 放；都没有的照旧 HLS。页面请求带 `dash: true` 和 `ytq`（`home.play` 一起带过去）；回答是
  `mode: "dash"`、基地址 `vod/<编号>/<令牌>/`，清晰度菜单是这个视频有的几档（`quality.site: "youtube"`；换一档就是另一路，
  `VodSource.variant`）。`…/manifest` 给两条轨的初始化段和分段表（`t`、`o`：n + 1 个时间、字节边界），从文件头里的 `sidx` 读
  （先读 64 KB，不够再读；yt-dlp 给了范围时一次取完），按 (视频, 格式) 缓存；`…/v`、`…/a` 和 `…/media` 一样转发 Range。
  上游请求经 YouTube 的代理（`ytvod.Fetcher`：经 `ytnode.open_tunnel` 打 HTTP CONNECT 或 SOCKS5 通道，长连接复用，跟随跳转），
  403 / 404 / 410 时带 `fresh=1` 重新取一次。`console.js` 的 `DashPlayer` 两个 SourceBuffer 往前缓冲 30 秒、往后留 30 秒（往回跳以后
  留在 120 秒以外的也清掉），跳转时按分段表重算（`dashResume`），掐掉用不上的请求，两条轨都取完了就结束流，别的和 `VodPlayer`
  一样（位置是 `currentTime`、倍速、画中画、进度、接着看、下一集）。第一帧之前出错就去掉 `dash` 再要（合体文件，再不行 HLS）；
  放到一半出错从同一个位置重开。**预取**：电脑版把看得见的前三个 YouTube 卡片（首页、搜索结果；滚动停下后再看）和鼠标停住、
  焦点所在的那个（250 毫秒）发给 `POST /api/yt/prefetch {ids, q}`（至多 6 个，同一个 10 分钟内只发一次；不是本机模式时回答
  `off: true`）；中转排队（新的在前，至多 8 个），一次一个，每分钟至多 12 个，有起播在取地址时停着，顺便把默认清晰度的索引取好。
  节点绝不让预取耽误真正的请求：yt-dlp 正忙时预取直接回答忙，正在跑时来了起播、搜索、列表就把它杀掉（同一个视频的起播则等它跑完）；
  被拒的预取至多再试三次。**马上有反应**：`playOnPc` 对每一种节目都马上打开窗口，放上卡片的封面（`#pcPoster`，没有时按 YouTube 的

## 18. 自己账号的几排和自动同步的关注（2026-10-26）

在分支 `desktop-accountfeeds` 上做的（基于 main `4202cbc`）。主人的要求：登录 B 站后能看到自己的观看记录和给自己的推荐，
YouTube 也一样，两边关注的 UP 主都自动同步，不用一个个再添加。只有家庭服务器和电脑客户端有：云端不保存任何人的 cookies，

**谁的数据。** B 站的几排和关注按调用者自己的 B 站登录（`bililogin.py`），家人只看得到自己的。YouTube 一台服务器只有一份
cookies（`ytsettings.py`，管理员的小号），所以 YouTube 的几排和 YouTube 订阅只给管理员看。

**首页的几排**（`server/relay/accountfeeds.py`），在「直播 · 正在播」后面，每一排都是第 8 节的「节目」，
`play` 是 `{kind: "feed", site, id, start?, part?}`：

| 排 | 来源 | 缓存 |
| --- | --- | --- |
| 关注的更新 | B 站 `/x/polymer/web-dynamic/v1/feed/all?type=video`（cookies、wbi 签名），和 YouTube `:ytsubs` 按时间排在一起 | 10 分钟 |
| B 站观看记录 | `/x/web-interface/history/cursor`（`progress` 是秒数，-1 看完了）；视频和番剧（整季，只在电脑上看）；直播、专栏不要 | 2 分钟 |

| YouTube 观看记录 | 节点 `/yt/feed?kind=history`（yt-dlp `:ythis`） | 5 分钟 |
| YouTube 推荐 | 节点 `/yt/feed?kind=rec`（yt-dlp `:ytrec`） | 10 分钟 |

yt-dlp 2026.10.21 的 `--extractor-descriptions` 里列着这三个关键词（`youtube:recommended`、`youtube:history`、
`youtube:subscriptions`）；观看记录和订阅要 cookies。节点按平铺列表、`--playlist-end 30` 跑（订阅加
`youtubetab:approximate_date`，好按时间和 B 站排在一起）；旧的远程节点回答 404，这一排说节点要更新。
`GET /api/feeds` 列出几排和各自的状态（`ready`、`login` 和需要什么、`hidden`）以及这个人的设置；`GET /api/feeds/row?id=`
回答一排：`state`（`ready`、`loading`、`login`、`blocked`、`error`、`hidden`）、`items`、`loading`、`message`。每个

再慢也不挡首页。「刷新」最多每 30 秒真去问一次；出错后 60 秒、被网络拦了（`bilibili.blocked`）5 分钟内不再问；登录被拒（`-101`）
和播放时一样记成失效。没登录时电脑版每个网站画一张小卡片（「登录 B 站」「导入 YouTube cookies」），点了去设置。
